## Scope
The Wayland backend: an in-house EI (libei) wire codec and client (receiver role for capture, sender role for
injection), portal clients (InputCapture, RemoteDesktop, Clipboard, Notification), the capture session manager
(barriers from edge segments, session recreation for mutter quirks), capturer, injector, displays from zones,
clipboard over the portal, permissions and degraded-mode reporting, compositor capability detection, the switch
indicator, and the Wayland branch of `internal/platform/host/host_linux.go`. Tray, session events, theme and
autostart reuse X1's `internal/platform/linux/*` packages. Hand verification happens only on the user's GNOME box;
KDE Plasma is in scope but untestable (R-09): code strictly to the portal and EI specifications and say "untested
on KDE" in the manual script. There is no compositor in CI; fake-bus tests run in CI (P2-Y1-020).

## Item P2-Y1-001
Vendor the EI protocol XML of the libei version sp3.md recorded (`third_party/libei/protocol.xml`, `LICENSE` (MIT
text from that release), `README.md` with URL, tag and commit). Generator `ei/gen` (stdlib `encoding/xml`): emit
`protocol_gen.go` with, per interface: name, version, requests and events in declaration order (opcode = index),
and argument kinds (uint32, int32, uint64, int64, float, string, new_id, object, fd) with names; plus typed opcode
constants (`OpHandshakeHandshakeVersion` style). `ei/doc.go`: package doc + `//go:generate go run ./gen -in
../../../../third_party/libei/protocol.xml -out protocol_gen.go`. Output deterministic and gofumpt-clean.

## Item P2-Y1-002
`wire.go`: header = object id (uint64) + length (uint32, includes the 16-byte header) + opcode (uint32), little-endian
(EI uses the native byte order of the EIS side; all supported targets are little-endian: assert at init via
`binary.NativeEndian` equality and error otherwise); arguments: 32-bit values 4 bytes, 64-bit 8 bytes, float as IEEE
754 32-bit, string = uint32 length incl. NUL + bytes + NUL + padding to 4 bytes (length 0 = null string),
new_id/object as uint64; fds are not in the byte stream (passed out of band, count derived from the signature).
`Encoder` appends into a reusable buffer; `Decoder.Next()` returns (header, args view) with a 64 KiB max message;
short, oversized, misaligned or overlong strings -> errors. Golden frames from SP3 tests. `FuzzDecodeFrame`.

## Item P2-Y1-003
`fd_linux.go`: read with `unix.Recvmsg` on the `*net.UnixConn`'s raw conn, parse `unix.ParseSocketControlMessage` +
`ParseUnixRights`, queue fds in arrival order for the decoder; keymap fds (ei_keyboard.keymap) are closed after
reading nothing from them (EdgeSync uses evdev codes, D-08) - close every received fd that no consumer claims, so
none leak. `fd_linux_test.go` uses `unix.Socketpair` (runs in the CI `test` job on ubuntu; host builds only).
