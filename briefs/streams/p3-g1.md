# Stream brief - P3 G1 Layout editor

Phase 3, parallel stream. Items: `briefs/plan-phase-3.md` section "G1". Owner tag: `[owner:G1]`.
Read first: `briefs/streams/p3-f.md` sections "Conventions" and "GUI design" (binding), then this brief.

## Scope
The free-form layout editor (D-04, D-30, D-51, D-60; FEAT-003, FEAT-006, FEAT-007, FEAT-147, FEAT-172): machines as
rigid groups of their monitors on a logical canvas, drag with snapping, zoom/pan, keyboard operation, validation,
apply/revert to the agent, read-only view on clients, synthetic layouts and frame benchmarks.

## Files you may touch
`gui/layouteditor/**` and `internal/i18n/locales/en/gui_layout.toml`; `cmd/edgesync/pages.go` only in P3-G1-010 with
the claim. Read, never edit: `internal/layout`, `internal/ipc`, `gui/state`, `gui/shell`, `gui/widgets`, `gui/theme`.

## Dependencies you use (read their code before starting)
- `internal/layout` (P1 C3): canvas model types, real-edge computation, overlap segments, snapping helper and layout
  validation. The editor never re-implements snapping, overlap or validation math: it calls these. If a needed function
  does not exist, report BLOCKED naming the missing function.
- `gui/state` (`Snapshot`, `Doer`), `gui/shell/vm` (`Intent`, routes), `gui/widgets`, `gui/widgets/guitest`,
  `gui/theme`, `gui/widgets/format`.
- IPC: `GetLayout`/`SetLayout`, `LayoutChanged`, `ListPeers`/`PeersChanged`, `GetStatus`/`StatusChanged`,
  `ActiveMachineChanged` (through the snapshot).

## Decisions
D-04 (free-form, snapping), D-30 (64 machines), D-51 (physical px + scale -> logical units; real edges; continuity
mapping), D-60 (server owns the layout, clients read-only), D-19/D-68 (strings), plus the P3-F decisions.

## Conventions
As in `p3-f.md`. Coordinates in the view model are canvas logical units (`float64` where the `internal/layout` types do
not dictate otherwise); the view converts with the viewport. Snap threshold: 12 dp on screen, converted to canvas units
by the view (`gtx.Dp(12)` / zoom) and passed to the view model.

## Screen: Layout editor (design)
- Toolbar (top): [Apply] (primary; Shortcut+S), [Revert], "Unapplied changes" badge when dirty, [Fit], [Zoom out],
  zoom percentage, [Zoom in].
- Canvas (fills): background Bg; each machine drawn as a rounded group (MachineFill) containing its monitors
  (MonitorFill, 1 dp ControlBorder outline), machine name centred above the monitors (ellipsis when too long), a badge
  row (Home / Online / Offline / Active; text + shape), monitor labels "2560 x 1440, 125 %" when the monitor is at
  least 80 dp wide on screen. Selected machine: 2 dp Primary outline with 2 dp offset. Dragged machine: 60 % opacity
  with the snap guides (GuideLine, 1 dp) and shared-edge segments (OverlapLine, 4 dp) of the candidate position.
- Side panel (right, 280 dp): "Machines" list (every placed machine; Tab-reachable rows; Enter or click selects);
  "Selected" details (name, short ID, monitors with resolution and scale, state, [Remove from layout] when allowed);
  "Not placed" list (paired peers not in the layout, each with [Place]); "Issues" list (errors first; click selects the
  machines involved).
- Banners (in the page, above the canvas): client read-only ("This computer is a client. The layout is managed on
  <server name>." / "... on the server."), conflict ("The layout was changed elsewhere." [Reload] [Keep mine]),
  synthetic mode ("Synthetic layout with N machines for performance testing. Changes cannot be applied."), apply error
  (agent message + [Dismiss]).
- States: Loading (until Layout and Peers are loaded), Error (slice load error + Retry), Home-only (server with no
  other machine placed or paired: the home machine plus the hint "Pair machines on the Machines page, then drag them
  next to this computer." and [Go to Machines] -> `machines`).
- Keyboard: see "Keyboard map" in `p3-f.md` (canvas section).

## Item P3-G1-001
`gui/layouteditor/vm/document.go`:
- `type MachineState struct{ Home, Online, Active bool }`; `type Machine struct{ ID string; Name string; Origin
  (canvas point); Monitors []Rect (canvas units); State MachineState }` (use the `internal/layout` types for points
  and rects where they exist).
- `type Model struct` with `func New(opts Options) *Model`, `Options{ SnapDisabledByAlt bool (always true), Synthetic
  int }`.
- `(*Model).Sync(snap state.Snapshot)`: builds the document from `snap.Layout` (machine origins + desktop snapshots)
  converting each monitor `Rect` from physical pixels to logical units with `ScalePermille` (logical = physical *
  1000 / scale), names from `snap.Peers` (home machine name from status), state flags from status/peers; when the
  document is clean, replace it; when dirty, keep it (P3-G1-006 handles conflicts).
- `Machines() []Machine` (placed), `Unplaced() []Peer` (paired peers not in the layout, sorted by name),
  `Selected() (string, bool)`, `Select(id)`, `Dirty() bool`, `Revert()`, `ApplyPayload() (layout value for SetLayout,
  error)` converting back to the IPC layout type with the same origins.
- Tests as named; `TestDocument_64Machines` builds 64 machines with 1-3 monitors each and checks counts and bounds.

## Item P3-G1-002
`gui/layouteditor/vm/viewport.go`: `type Viewport struct{ Zoom float64; Pan Point (screen px offset); Size (screen
px) }`; `CanvasToScreen`, `ScreenToCanvas` (exact inverses), `ZoomAt(screen Point, factor float64)` keeps the canvas
point under the cursor fixed, zoom clamped to [0.02, 4.0]; `Fit(bounds Rect, marginPx float64)` centres and scales the
bounds into the viewport (a single machine fits with the same margin); `PanBy(dx, dy)`; `HitTest(screen Point)
(string, bool)` returns the selected machine first if hit, otherwise the topmost (last drawn) machine whose group bounds
contain the point.

## Item P3-G1-003
`gui/layouteditor/vm/drag.go` (sonnet item; state machine shared by pointer and keyboard paths):
- `BeginDrag(id string, at screen Point) error` (ErrReadOnly when read-only; selects the machine), `DragTo(at Point,
  snap bool, thresholdCanvas float64) DragFeedback`, `EndDrag()` (commits the new origin; marks dirty only when the
  origin changed), `CancelDrag()` (restores the origin from BeginDrag).
- Movement = canvas delta of the pointer since BeginDrag. With `snap`, call the `internal/layout` snapping helper with
  the moving machine's group, all other placed groups, and `thresholdCanvas`; apply its offset.
- `DragFeedback{ Guides []Segment; Overlaps []Segment; Snapped bool }`: guides = the snap lines from the helper;
  overlaps = shared real-edge segments between the moving machine at its candidate position and its neighbours
  (from `internal/layout`).
- `BenchmarkDragTo64`: 64 machines, 100 `DragTo` calls per iteration; report ns/op and allocs/op.

## Item P3-G1-004
`gui/layouteditor/vm/keyboard.go`: `Nudge(dx, dy int)` moves the selected machine by 1 or 10 logical units (the view
passes 10 with Shift) and marks dirty; `SelectNext()` / `SelectPrev()` in reading order (top edge, then left edge,
then ID); `RemoveSelected() error` (the home machine returns `ErrHomeNotRemovable`; removed machines appear in
`Unplaced()`); `Place(id string) error` places a machine to the right of the rightmost placed machine, top edges
aligned, touching (zero gap), and selects it. All mutators return `ErrReadOnly` in read-only mode.

## Item P3-G1-005
`gui/layouteditor/vm/validate.go`: `Issues() []Issue` with `Issue{ Kind IssueKind; Severity (Error|Warning); Machines
[]string; Text string }`; kinds: Overlap (Error), DuplicateMachine (Error), Unreachable (Warning: no chain of shared
edges to the home machine), HomeWithoutNeighbours (Warning). Map the `internal/layout` validation result; texts from
`gui.layout.issue.*`. `CanApply() bool`: dirty, not read-only, no Error issues. `EdgeLinks(id) []Segment`: shared
real-edge segments of a machine with its neighbours (shown for the selected machine).

## Item P3-G1-006
`gui/layouteditor/vm/sync.go`:
- Read-only when the role in the snapshot is client (`ReadOnlyReason{Client, ServerName}`) or the model is synthetic
  (`ReadOnlyReason{Synthetic}`); all mutators return `ErrReadOnly`.
- `Sync` on a clean document replaces it; on a dirty document with a changed layout revision (or changed content when
  no revision exists) sets `Conflict() == true` and keeps the user's document.
- `ResolveConflict(reload bool)`: reload -> discard local changes, take the agent layout; keep -> clear the conflict
  flag, the next Apply overwrites.
- `Apply(d state.Doer) state.OpID` calls `SetLayout(ApplyPayload())`; `ApplyResult(snap)`: on success the document is
  clean and a transient "Layout applied" banner is requested; on failure the document stays dirty and `ApplyError()`
  returns the agent message.
- Names follow peer renames; the Active flag follows `ActiveMachineChanged`/status.

## Item P3-G1-007
`gui/layouteditor/canvas.go`: draws the canvas from `Model` + `Viewport` + the current `DragFeedback` as described in
"Screen: Layout editor". Every machine group emits a semantic node (class button, label = machine name, description =
state text, selected flag). Monitor labels hidden below 80 dp on-screen width. Home-only hint state. Both themes.
Use only `gui/theme` colours. Strings `gui.layout.*` in `gui_layout.toml`.

## Item P3-G1-008
`gui/layouteditor/input.go` (sonnet item): one canvas-level event handler (`event.Op` on the canvas area) with
`pointer.Filter{Kinds: Press|Drag|Release|Cancel|Scroll, ScrollY/ScrollX bounds}` and `key.Filter`s for the canvas keys
plus `key.FocusFilter`.
- Left press on a machine: focus canvas, `BeginDrag`; drag: `DragTo(pos, snap = Alt not held, threshold)`; release:
  `EndDrag`; `pointer.Cancel` or Escape during a drag: `CancelDrag`. Left press on empty canvas: clear selection.
- Middle press + drag: `PanBy`. Scroll with Shortcut: `ZoomAt(pos, 1.1^(-steps))`; scroll without modifier: `PanBy`.
- Keys when the canvas is focused: arrows (Shift = 10) `Nudge`; PageDown/PageUp select next/previous; Delete
  `RemoveSelected`; Escape cancel drag or clear selection; F and Shortcut+0 fit; Shortcut+= and Shortcut+- zoom by
  1.25 around the viewport centre.
- In read-only mode only selection, pan, zoom and fit react.
- Tests drive everything through `guitest` (drag sequences with `Drag`, modifiers via the event modifiers).

## Item P3-G1-009
`gui/layouteditor/toolbar.go` and `panel.go`: toolbar and side panel as in "Screen: Layout editor". [Apply] enabled
only when `CanApply()`, shows pending state from the op, Shortcut+S triggers it; [Revert] enabled when dirty; zoom
label "<n> %". Panel lists are Tab-reachable rows; Enter selects. Issue rows select all involved machines' first
machine and scroll the viewport to it (`Fit` on its bounds is acceptable). Banners per "Screen: Layout editor" using
`widgets.Banner`.

## Item P3-G1-010
`gui/layouteditor/page.go`: `Page` implementation for route `layout` composing toolbar, canvas, panel, banners and
states; keeps one `Model` across navigation (created by the factory, not per frame); consumes `layout{select: id}` via
`Nav.TakeParams`; uses `vm.NewSynthetic(n)` when `Env.Options.SyntheticMachines > 0`. Append the page factory to
`cmd/edgesync/pages.go` (claim). `TestPages_NoDuplicateRoutes` must stay green.

## Item P3-G1-011
- `gui/layouteditor/vm/synthetic.go`: `NewSynthetic(n int) *Model` (1 <= n <= 64): deterministic machines named
  "Synthetic 01".., monitor patterns cycling 1920x1080@100 %, 2560x1440@125 % + 1920x1080@100 %, 3840x2160@150 % x 2 +
  2560x1440@125 % (1-3 monitors), placed in rows of 8 touching each other so every machine is reachable; read-only
  reason Synthetic.
- `gui/layouteditor/bench_test.go`: `BenchmarkEditorFrame64` (guitest frame of the page at 1920x1080 px scale 1.0 with
  64 synthetic machines), `BenchmarkEditorDragFrame64` (one `DragTo` + frame per iteration). Report ns/op and
  allocs/op; these are the PB-19 CPU-side proxy (PB-19 itself is measured by the user with `-perflog`).
