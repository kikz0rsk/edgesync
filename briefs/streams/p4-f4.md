# Stream brief - P4 F4 Linux X11 file paste, XDND and GUI drop

Phase 4 stream. Items: `briefs/plan-phase-4.md` section "F4". Owner tag `[owner:F4]`.

## Scope
Implement `platform.FileClipboard` (FEAT-110) and `platform.DragDrop` (FEAT-111) for X11 with `github.com/jezek/xgb`
(pure Go, `CGO_ENABLED=0`), and native file drop onto the Gio X11 window via `XdndProxy` (FEAT-112).

X11 file managers need real local paths (R-27). Lazy paste is therefore fetch-on-request:
1. The selection reply for `text/uri-list` is delayed until `transfer.Stager` has staged the files.
2. The reply then carries `file://` URIs of the staged copies.

The variant is decided at P4-F4-001 from sp3.md.

The user has no X11 session (R-08): verification is Xvfb on CI plus Xephyr on the GNOME box.

## Reference: XDND v5 ClientMessage layouts (format 32, data.l[0..4])

| Message | Direction | l[0] | l[1] | l[2] | l[3] | l[4] |
|---|---|---|---|---|---|---|
| XdndEnter | source -> target | source window | bit 0: more than 3 types (read `XdndTypeList` on the source); bits 24-31: version | type 1 | type 2 | type 3 |
| XdndPosition | source -> target | source window | 0 | (root x << 16) \| root y | timestamp | action atom |
| XdndStatus | target -> source | target window | bit 0: accept; bit 1: send position updates even inside the rectangle | (x << 16) \| y of the no-update rect | (w << 16) \| h | accepted action atom (None when refusing) |
| XdndLeave | source -> target | source window | 0 | 0 | 0 | 0 |
| XdndDrop | source -> target | source window | 0 | timestamp | 0 | 0 |
| XdndFinished | target -> source | target window | bit 0: drop accepted (v5) | performed action atom (None when refused) | 0 | 0 |

Properties:
- `XdndAware` on the toplevel (type ATOM, value 5).
- `XdndProxy` (type WINDOW; set on the target window and on the proxy itself, pointing to the proxy).
- `XdndTypeList` on the source (ATOM list).

Data comes from `ConvertSelection(XdndSelection, target, property, requestor, time)`. Action is always `XdndActionCopy` (D-62).

Selection rules (ICCCM):
- The owner answers `SelectionRequest` by writing the property on the requestor and sending `SelectionNotify`. Property None means refusal.
- Data larger than the connection's maximum request size (`xgb` setup `MaximumRequestLength` * 4 minus header) uses INCR:
  1. Set the property with type INCR and the total size.
  2. On each `PropertyNotify(Deleted)` of that property on the requestor, write the next chunk.
  3. Finish with a zero-length chunk.
- `TARGETS` lists the supported target atoms.

Atoms used: `CLIPBOARD`, `TARGETS`, `MULTIPLE`, `INCR`, `ATOM`, `text/uri-list`, `x-special/gnome-copied-files`, `x-kde-passwordManagerHint`, `application/x-kde-cutselection`, `XdndAware`, `XdndProxy`, `XdndTypeList`, `XdndSelection`, `XdndEnter`, `XdndPosition`, `XdndStatus`, `XdndLeave`, `XdndDrop`, `XdndFinished`, `XdndActionCopy`, `UTF8_STRING`.

## Item P4-F4-003
- `vfile/reply.go` (pure): `type replyPlan` for one owned selection. Input events: `RequestReceived(requestor, target, property, time)`, `StagingDone(paths)`, `StagingFailed(err)`, `SelectionCleared`. Output actions: `WriteProperty`, `SendNotify(property or None)`, `StartStaging(manifestID)`.
  - TARGETS is answered immediately with `[TARGETS, text/uri-list, x-special/gnome-copied-files]`.
  - The first file-target request starts staging. Later requests for the same manifest queue up and are all answered when staging ends.
  - Failure answers None for every waiting request and raises `files.pasteFailed`.
  - `x-special/gnome-copied-files` always uses the `copy` verb (`vfile.EncodeGnomeCopiedFiles`).
- `vfile/fileclipboard_linux.go`:
  - Create an InputOnly window.
  - **WatchFiles:** `xfixes.SelectSelectionInput(win, CLIPBOARD, SetSelectionOwner|SelectionWindowDestroy|SelectionClientClose)`. On notify where the owner is not our window, increment the local seq, then:
    1. Convert TARGETS.
    2. If `text/uri-list` or `x-special/gnome-copied-files` is present, convert the best target. INCR is supported.
    3. Decode with `vfile.DecodeURIList`/`DecodeGnomeCopiedFiles` and call `fn(seq, paths)`.
    4. Cut markers are ignored (D-62).
  - **OfferFiles:** `SetSelectionOwner(CLIPBOARD, win, CurrentTime)` and check with `GetSelectionOwner`; failure is an error. Drive `replyPlan` from `SelectionRequest` events, staging via `transfer.Stager` in a goroutine. URI lists above the max request size use INCR.
  - On `SelectionClear`, the provider gets Abandoned unless it has an outcome.
  - **Close:** release ownership if owned, destroy the window, close the connection.

## Item P4-F4-006
- `dnd/target.go` (pure): target state machine for one strip. On Enter it records the source and types. With `text/uri-list` it requests conversion of `XdndSelection` to `text/uri-list` (action), then:
  - when paths arrive: emit `DragOutEnter{paths}` and reply Status accept/Copy;
  - when the uri-list is absent: emit `DragOutUnsupported` and reply Status refuse.
  - Position replies with the current status.
  - Leave emits `DragOutLeave`.
  - Drop: with a pending remote outcome (P4-F4-008), finish with it; without one, emit `DragOutDrop` and reply Finished(refused).
- `dnd/edge_linux.go`:
  - per strip, an override-redirect InputOutput window (1 x length, or length x 1, at the real edge inside the monitor; geometry as in F2's `Strips` but 1 px, computed in a pure helper), mapped and raised, with `XdndAware=5`;
  - background None, no visible pixels;
  - its input shape set to an empty region via `xfixes.SetWindowShapeRegion(win, shape.SkInput, 0, 0, emptyRegion)` when unarmed, and reset (region None) when armed, so XDND sources find it only during a drag.

  Verify the SHAPE kind constant and the XFixes request in the xgb packages.
- `dnd/dragdrop_linux.go`: the `DragDrop` type, its connection and event loop dispatching ClientMessage, SelectionNotify and PropertyNotify to the state machines.

## Item P4-F4-007
While a foreign X11 drag holds the pointer grab, `xproto.GrabPointer` fails with AlreadyGrabbed, so the normal capturer cannot grab.

Passive mode (decision logic in `capture_passive_linux.go` with a pure helper tested on the host):
- When `Grab` gets AlreadyGrabbed and the DnD coordinator marked a drag active, the capturer:
  - does not grab;
  - takes motion deltas from XI2 `RawMotion` events on the root (binding from X1);
  - reports `KindMotion` with DX/DY as when grabbed;
  - keeps reporting button and key events from XI2 raw events.

  The physical pointer stays clamped at the edge over our strip window, and the release reaches the source normally, which drops onto our strip.
- `Ungrab` in passive mode only leaves passive mode.

The parent-resolved X1 capturer files get the minimal hook: the AlreadyGrabbed branch delegates to passive mode. X1's conformance suite must still pass on CI.

## Item P4-F4-008
`dnd/finish.go` (pure, named `finish_test.go` for tests) and `dnd/finish_linux.go`.

Reconcile two independent events:
- the remote outcome from `FinishOutgoing(accepted)`;
- the source's own `XdndDrop`, which happens when the user physically releases (passive mode) or never happens (cancel).

Rules:
- Drop arrives first: wait for the outcome up to the handshake timeout (D-57), then send `XdndFinished(accepted, accepted ? XdndActionCopy : None)`.
- Outcome arrives first: store it and apply on Drop.
- `XdndLeave` from the source (Escape pressed locally): emit `DragOutLeave`. The coordinator cancels the remote side.
- Never perform Move.

## Item P4-F4-009
`dnd/source.go` (pure) source state machine plus `dnd/incoming_linux.go`. `BeginIncoming`:
1. Own `XdndSelection` with a source window and set `XdndTypeList` = [`text/uri-list`].
2. `GrabPointer` on the source window with motion events. We are the client machine: the server injects motion via XTest, so the grab receives it.
3. On each motion, find the target under the pointer: `QueryPointer` from root down through children, the first toplevel with `XdndAware`, following `XdndProxy` when present. Send Enter/Leave on target changes and Position on motion. Track Status accept.
4. `Release()`: if accepted, send `XdndDrop` with the last timestamp; otherwise Leave and finish with `Dropped=false`.
5. Answer `SelectionRequest` on `XdndSelection` for `text/uri-list` by staging the manifest (`Stager.Materialize`) and replying with URIs, using the same delayed-reply rules and INCR as `reply.go`.
6. `XdndFinished` gives `DropResult{Dropped: accepted}`.
7. `Cancel()` sends Leave. Ungrab in every terminal state.
