# Stream brief - P4 F2 Windows cross-screen drag-and-drop and GUI file drop

Phase 4 stream. Items: `briefs/plan-phase-4.md` section "F2". Owner tag `[owner:F2]`.

## Scope
Implement `platform.DragDrop` for Windows:
- **Outgoing (FEAT-104):** an Explorer drag reaches an edge strip of a machine with a neighbour. Transparent topmost drop-target windows along the real edges receive `DragEnter` and read CF_HDROP. `FinishOutgoing` later ends the source's modal drag loop.
- **Incoming (FEAT-105):** `DoDragDrop` from an agent window with the F1 virtual-file data object plus `IDataObjectAsyncCapability`. Release and cancel are driven by the coordinator.
- **GUI drop (FEAT-106):** an `IDropTarget` registered on the Gio HWND.
- **Wiring:** the cross-platform wiring of drop areas into the Machines page and layout editor (P4-F2-012).

## Conventions (binding)
- **Decisions:** D-12, D-13, D-39, D-49, D-50 (the `dwExtraInfo` marker on injected events), D-62, D-63, D-64, D-75. Plus the P4-F2-001 scope decision and the P4-F-002 depguard allowance.
- **COM:** the same rules as F1 (`briefs/streams/p4-f1.md`, "Conventions" and "Reference"): non-Go memory for objects, one callback per method, STA confinement, verify every constant.
- **STA:** all OLE drag-and-drop runs on one dedicated STA thread per `DragDrop` instance. `RegisterDragDrop` must be called on the thread that owns the window and has called `OleInitialize`. `DoDragDrop` runs its own modal loop on that thread and still services incoming COM calls (Explorer's IStream reads) because it pumps messages.
- **Never MOVE:**
  - drop-target methods only ever write DROPEFFECT_COPY or DROPEFFECT_NONE to `*pdwEffect`;
  - `DoDragDrop` is called with `dwOKEffects = DROPEFFECT_COPY` only (D-62).
- **Injected events** (FinishOutgoing, incoming button state) use `SendInput` with `dwExtraInfo` = the EdgeSync marker defined by W1 (D-50), so the capturer ignores them.
- **Integration tests:** `//go:build integration && windows`. No em dashes or en dashes. Commits `feat(win): ...` or `feat(gui): ...`, body `Item: <id>`, no attribution trailers.

## Reference

Vtables (after IUnknown 0-2):
- IDropSource: 3 QueryContinueDrag(fEscapePressed BOOL, grfKeyState DWORD) HRESULT, 4 GiveFeedback(dwEffect DWORD).
- IDropTarget: 3 DragEnter(pDataObj, grfKeyState, pt POINTL by value, pdwEffect *DWORD), 4 DragOver(grfKeyState, pt, pdwEffect), 5 DragLeave(), 6 Drop(pDataObj, grfKeyState, pt, pdwEffect).
- IDataObjectAsyncCapability: 3 SetAsyncMode(fDoOpAsync BOOL), 4 GetAsyncMode(pfIsOpAsync *BOOL), 5 StartOperation(pbcReserved), 6 InOperation(pfInAsyncOp *BOOL), 7 EndOperation(hResult HRESULT, pbcReserved, dwEffects DWORD).

POINTL by value: an 8-byte struct passed in one 64-bit register on amd64 and arm64. With `syscall.NewCallback` it arrives as one `uintptr`:
- `x = int32(uint32(v))`
- `y = int32(uint32(v >> 32))`

Verify against the Windows x64 calling convention docs and test with negative coordinates.

IIDs (verify): IDropSource `00000121-0000-0000-C000-000000000046`, IDropTarget `00000122-0000-0000-C000-000000000046`, IDataObjectAsyncCapability `3D8B0590-F691-11D2-8EA9-006097DF5BD4`.

Constants (verify):
- DRAGDROP_S_DROP 0x00040100, DRAGDROP_S_CANCEL 0x00040101, DRAGDROP_S_USEDEFAULTCURSORS 0x00040102.
- MK_LBUTTON 0x0001.
- WS_EX_LAYERED 0x00080000, WS_EX_TRANSPARENT 0x00000020, WS_EX_TOPMOST 0x00000008, WS_EX_TOOLWINDOW 0x00000080, WS_EX_NOACTIVATE 0x08000000.
- WS_POPUP 0x80000000, LWA_ALPHA 0x2, GWL_EXSTYLE -20.
- SWP_NOMOVE 0x2, SWP_NOSIZE 0x1, SWP_NOACTIVATE 0x10, SWP_FRAMECHANGED 0x20, HWND_TOPMOST -1.
- INPUT_MOUSE 0, INPUT_KEYBOARD 1, MOUSEEVENTF_LEFTDOWN 0x2, MOUSEEVENTF_LEFTUP 0x4, VK_ESCAPE 0x1B, KEYEVENTF_KEYUP 0x2.

## Item P4-F2-005
`dnd/geometry.go` (build-tag free): `func Strips(edges []platform.EdgeSegment) []Strip`. A `Strip` is a rect in virtual-desktop physical pixels, 2 px thick, inside the monitor bounds, spanning `From..To` of the segment:
- left side: x = At .. At+2;
- right side: x = At-2 .. At;
- top and bottom likewise.

Also `func (s Strip) Contains(p platform.Point) bool`.

## Item P4-F2-006
- `dnd/dragdrop_windows.go`: `type DragDrop` implementing `platform.DragDrop`. It owns the STA, the strip windows, the watcher fan-out, the active incoming drag and the active outgoing state.
- `dnd/edge_windows.go`:
  - **SetEdges (on the STA):** destroy the previous strip windows (`RevokeDragDrop` first), then per strip create a `WS_POPUP` window with `WS_EX_LAYERED|WS_EX_TOPMOST|WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE|WS_EX_TRANSPARENT`, alpha 1 via `SetLayeredWindowAttributes(LWA_ALPHA)`, shown without activation, and call `RegisterDragDrop(hwnd, target)`.
  - **Arm(true):** clear WS_EX_TRANSPARENT on every strip (`SetWindowLongPtrW` + `SetWindowPos(SWP_FRAMECHANGED|...)`) so `WindowFromPoint` finds them during an OLE drag. **Arm(false):** set it again. The button is already down when arming, so the press went to the window underneath and its mouse capture stays there; strips only become OLE drop candidates.
  - **DragEnter:** with CF_HDROP, read the paths, write DROPEFFECT_COPY and emit `DragOutEnter{Paths, At, Edge}`. Without it, write DROPEFFECT_NONE and emit `DragOutUnsupported`.
  - **DragOver:** COPY when Enter accepted, else NONE.
  - **DragLeave:** emit `DragOutLeave`.
  - **Drop:** if a remote finish is pending (P4-F2-007), return its effect. Otherwise emit `DragOutDrop` and write NONE.
- Tests drive the target implementation directly with a fake window factory and a fake `Foreign`.

## Item P4-F2-007
`dnd/finish_windows.go`: `FinishOutgoing(ctx, accepted)`.
- Precondition: an outgoing drag is active. Otherwise return `errNoActiveDrag`, and a second call returns nil (idempotent).
- The W1 capturer parks the cursor at the contact point while grabbed (requirement checked at P4-F-001), so the cursor is over the strip window.
- Accepted:
  1. Set the pending effect to DROPEFFECT_COPY.
  2. Inject `MOUSEEVENTF_LEFTUP` with the marker. The source's `DoDragDrop` loop then sees the release and calls our `Drop`, which returns COPY.
- Not accepted:
  1. Set the pending effect to NONE.
  2. Inject Escape down/up with the marker. The source's `QueryContinueDrag` cancels.
- Wait up to 2 s for `Drop`/`DragLeave` confirmation, otherwise return a typed error (logged; the coordinator surfaces `dnd.failed`).
- Tests use a `SendInput` seam.

## Item P4-F2-008
`dnd/incoming_windows.go`: `BeginIncoming(ctx, m, p, at)`.
1. Reject when an incoming drag is active.
2. On the STA, create a 32x32 transparent layered tool window centred at `at`.
3. Build the F1 data source with `AsyncCapability: true` and the data object. Create a drop source whose `QueryContinueDrag` returns:
   - DRAGDROP_S_CANCEL when cancel was requested, `ctx` is done, or `fEscapePressed`;
   - DRAGDROP_S_DROP when `Release()` was called;
   - S_OK otherwise.

   Physical key state is ignored: the remote user owns the button.
4. Follow sp2.md's recommended start sequence. Default: inject `LEFTDOWN` (marker) at `at` so the system button state matches a drag, then call `DoDragDrop(obj, src, DROPEFFECT_COPY, &effect)` on the STA.
5. After `DoDragDrop` returns, inject `LEFTUP` (marker) if the system still reports the left button down (`GetAsyncKeyState`), restoring a clean state.
6. Result: `Dropped = effect == DROPEFFECT_COPY`, `Target = ""`.

`IncomingDrag` is returned immediately; `Wait` blocks until the loop ends.

## Item P4-F2-013
`qa/manual/p4-f2-dnd-windows.md`. Machines: PC1 (server), PC2 (client), wired.

Scenarios:
1. Drag a file from PC1 Explorer across the edge onto a PC2 Explorer folder, then onto PC2's desktop.
2. Drag a folder tree with unicode names.
3. Drag 1 GiB: Explorer extracts asynchronously and stays responsive; the queue shows progress.
4. PC2 to PC1 (client origin).
5. Escape during a remote drag cancels both sides; PC1's source window is unaffected.
6. Move back to PC1 during the drag: the local drag continues and can be dropped locally.
7. Release over PC2 where no target accepts (taskbar): nothing transferred.
8. A drag of non-file content (text from a browser) reaching the edge: notification `dnd.unsupportedSource`.
9. A drop onto an elevated Explorer window on PC2: record behaviour vs the P4-F2-001 decision.
10. Pull PC2's cable during a drag: cancelled on both sides.
11. GUI drop: drag files from Explorer onto a machine tile in the EdgeSync window and onto a machine in the layout editor; the transfer appears in the queue; drop outside a tile is ignored.
12. Cut-drag (Shift held) still copies (D-62).

Cleanup and safety sections included.
