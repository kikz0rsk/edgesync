# Stream brief - P1 C2 PKI, SPAKE2, pairing, peers, discovery, Wake-on-LAN

Phase 1 core stream. Items: `briefs/plan-phase-1.md` section "C2". Owner tag: `[owner:C2]`. Starts after the
CONTRACT FREEZE (P1-F-022).

## Scope
Trust and reachability: identity certificates and their storage (per-user; the Windows machine identity behind the
service is P2 W2, but the `crypto.Signer` hook it needs is built here), SPKI pin verification, SPAKE2 per RFC 9382,
the pairing code and protocol, the peer store, mDNS discovery plus manual peers, and Wake-on-LAN.

## Owned paths
`internal/pki/**`, `internal/spake2/**`, `internal/pairing/**`, `internal/peers/**`, `internal/discovery/**`,
`internal/wol/**`, `qa/manual/p1-c2-*.md`; `go.mod`/`go.sum` with a claim in the items that add a dependency.
Leave alone: transport and session (C1) - use their exported APIs; frozen contracts.

## Conventions (binding)
- Decisions: D-14, D-15, D-41, D-42, D-43, D-45 (atomic writes), D-57, D-70, D-75. Research: `briefs/research-go-ecosystem.md`
  3.3-3.5; `briefs/spikes/sp5.md` (SPAKE2 encodings and API recommendation, mDNS library choice); checklist
  `qa/security-review.md` sections 1, 2, 8.
- Crypto: only the standard library (`crypto/hkdf` from Go 1.24+, `crypto/hmac`, `crypto/sha256`, `crypto/subtle`,
  `crypto/ecdsa`, `crypto/x509`) and `filippo.io/nistec` v0.0.4. `golang.org/x/crypto` is not a direct dependency
  (not pinned for direct use). Randomness only from `crypto/rand` (injectable `io.Reader` for tests).
- Secrets (codes, keys, shares, confirmation MACs) are never logged; use `logging.Secret` if a value must appear.
- Atomic file writes: write `<name>.tmp-<random>` in the same directory, `f.Sync()`, close, `os.Rename`, then sync the
  directory on unix. Never leave temp files on error paths.
- Tests touching multicast or broadcast carry `//go:build integration`; loopback unicast is host-safe.
- No em dashes or en dashes. Commit scopes: `pki`, `spake2`, `pairing`, `peers`, `discovery`, `wol`.

## Item P1-C2-001
`internal/pki` package doc: "Package pki creates and stores EdgeSync identity certificates and verifies peer pins
(D-41, D-42)."
```go
type Identity struct { Cert *x509.Certificate; Signer crypto.Signer }
func Generate(name string, now time.Time, rnd io.Reader) (*Identity, error)
func FromSigner(cert *x509.Certificate, s crypto.Signer) (*Identity, error) // public keys must match (W2's service signer proxy plugs in here)
func (id *Identity) NeedsReissue(now time.Time) bool                       // NotAfter - now < 30 days
func (id *Identity) Reissue(name string, now time.Time, rnd io.Reader) (*Identity, error) // same key, new cert
func (id *Identity) TLSCertificate() tls.Certificate                       // {Certificate: [][]byte{Cert.Raw}, PrivateKey: Signer, Leaf: Cert}
func (id *Identity) PeerID() peerid.ID
```
Certificate template: ECDSA P-256 key (`ecdsa.GenerateKey(elliptic.P256(), rnd)`), serial = 128 random bits
(positive `big.Int`), Subject CN = name (truncated to 64 bytes on a UTF-8 boundary), NotBefore = now - 1 h, NotAfter
= now + 10 years (`AddDate(10, 0, 0)`), KeyUsage DigitalSignature, ExtKeyUsage ServerAuth + ClientAuth,
BasicConstraintsValid true, IsCA false, self-signed. `TestIdentity_RemoteSignerHandshake` wraps the key in a
`crypto.Signer` decorator that counts Sign calls and completes a TLS 1.3 loopback handshake with
`transport`-independent `tls.Server`/`tls.Client` (no C1 dependency in this item).

## Item P1-C2-002
`store.go` (shared):
```go
type Store interface { LoadOrCreate(name string, now time.Time) (*Identity, error) }
var (ErrServiceRequired, ErrInsecurePermissions, ErrInvalidMode = ...)
func NewStore(mode, dir string, rnd io.Reader) (Store, error)  // mode "user" -> file store; "machine": windows -> ErrServiceRequired (P2 W2 adds the service-backed store), other OS -> ErrInvalidMode
```
File layout in `dir` (from `internal/paths` config dir + `identity/`, passed in by the agent): `cert.pem` and the key
file. LoadOrCreate: missing both -> Generate + save; cert present and `NeedsReissue` -> Reissue + save cert; key
without cert or cert without key -> error (never silently regenerate: a new key changes the peer id and breaks every
pin). PEM helpers and the atomic write helper live here.
`store_unix.go` (`//go:build !windows`): `key.pem` = PKCS#8 PEM ("PRIVATE KEY"), mode 0600; dir 0700 (created with
`os.MkdirAll` then `os.Chmod`, because umask). Load refuses a key file whose mode has any group/other bit
(`ErrInsecurePermissions`, like ssh) and a dir with group/other write.

## Item P1-C2-005
`internal/spake2` package doc: "Package spake2 implements SPAKE2 (RFC 9382) for the ciphersuite
SPAKE2-P256-SHA256-HKDF-HMAC on filippo.io/nistec." Port the validated spike implementation
(`spikes/spake2/`), restructured into this API:
```go
type Role uint8 // RoleA = 1 (initiator), RoleB = 2 (responder)
var (ErrInvalidShare, ErrConfirmation, ErrState = ...)
type Exchange struct{ ... }
func New(role Role, password []byte, idA, idB, aad []byte, rnd io.Reader) (*Exchange, error)
func (e *Exchange) Share() []byte                                 // own pA (A) or pB (B), 65-byte uncompressed SEC1
func (e *Exchange) Finish(peerShare []byte) (confirm []byte, err error) // computes K, TT, Ke, Ka, KcA, KcB; returns own MAC
func (e *Exchange) Verify(peerConfirm []byte) (key []byte, err error)    // constant-time; returns Ke on success
```
- Constants M and N exactly from RFC 9382 section 6 (P-256 entries), parsed once at package init into
  `*nistec.P256Point` values (the only package-level values, immutable after init).
- Ephemeral scalars x, y: 32 random bytes, rejection-sampled until 0 < s < n.
- Password scalar (production): `w = OS2IP(HKDF-SHA256(secret = password, salt = "EdgeSync SPAKE2 w v1", info = idA
  || 0x00 || idB, L = 48)) mod n` (wide reduction keeps bias below 2^-128). RFC 9382 section 3.2 recommends an
  MHF; it is omitted deliberately because codes are single-use with 3 attempts and SPAKE2 transcripts give no offline
  oracle; the security-review gate checks this rationale. If `briefs/spikes/sp5.md` recorded a different
  derivation, STOP and report BLOCKED (the parent decides at the freeze).
- Shares: pA = x*P + w*M, pB = y*P + w*N; K = x*(pB - w*N) for A, y*(pA - w*M) for B (cofactor 1).
- TT = len||A || len||B || len||pA || len||pB || len||K || len||w with 8-byte little-endian lengths, encodings
  exactly as the spike reproduced the RFC vectors (uncompressed points, w as 32-byte big-endian).
- Ke || Ka = SHA-256(TT) halves; KcA || KcB = HKDF(Ka, salt = nil, info = "ConfirmationKeys" || AAD, 32);
  cA = HMAC-SHA256(KcA, TT), cB = HMAC-SHA256(KcB, TT).
- Peer share: `nistec.NewP256Point().SetBytes` (rejects off-curve), plus an explicit identity-point rejection.
- `export_test.go` exposes `newWithScalars(role, w, x/y []byte, ...)` for the vectors.
- `testdata/rfc9382_p256.json`: every P-256 vector of RFC 9382 Appendix B (fields A, B, w, x, pA, y, pB, K, TT, Ke,
  Ka, KcA, KcB, cA, cB as hex), transcribed from https://www.rfc-editor.org/rfc/rfc9382.txt with the section cited
  in a `"source"` field.
- Scalar arithmetic needing reduction or negation (w mod n, n - w) uses `math/big` once per exchange on values
  derived from the password; record this in a short comment (non-obvious, reviewed by the security gate).

```go
type CodeIssuer struct{ ... } // one active code at a time
```

## Item P1-C2-008
`protocol.go`, `initiator.go`, `responder.go`. Messages: `msg.PairHello`, `msg.Spake2Share`, `msg.Spake2Confirm`,
`msg.PairResult` framed on `PairingConn.Stream()` with `transport.NewMessageStream(rw, msg.MaxPairingBytes)`.
```go
type LocalInfo struct { Name, OS string; Role msg.Role; ID peerid.ID }
type Result struct { Peer peerid.ID; Name, OS string; Role msg.Role }
type ProgressKind uint8 // ProgressHello = 1, ProgressCodeShown, ProgressVerifying, ProgressWrongCode, ProgressSucceeded, ProgressFailed
type Progress struct { Kind ProgressKind; AttemptsLeft int; Code string /* responder only, for display */; Expires time.Time; Failure msg.PairFailure }
type Responder struct { Local LocalInfo; Codes *CodeIssuer; Rand io.Reader; OnProgress func(Progress) }
func (r *Responder) Serve(ctx context.Context, pc transport.PairingConn) (Result, error)
type Initiator struct { Local LocalInfo; Rand io.Reader; Code func(ctx context.Context, attemptsLeft int) (string, error); OnProgress func(Progress) }
func (i *Initiator) Pair(ctx context.Context, pc transport.PairingConn) (Result, error)
```
Sequence (I = initiator = role A, R = responder = role B):
1. I -> R PairHello; R -> I PairHello. Each side checks `hello.ID == peerid.FromCertificate(pc.PeerCertificate())`
   and protocol version equality (mismatch -> PairResult versionMismatch, close).
2. R ensures an active code (`Codes.Active()` or `Issue()`), reports ProgressCodeShown with code and expiry.
3. `aad = cs.ExportKeyingMaterial("EXPORTER-EdgeSync-pairing-v1", nil, 32)`; idA = I's id bytes, idB = R's id
   bytes (the 52-char strings).
4. Loop while attempts remain: I gets the code from `Code(ctx, attemptsLeft)`; I -> R Spake2Share(pA);
   R -> I Spake2Share(pB) (R computes with the active code; a code that expired meanwhile -> PairResult expired);
   I -> R Spake2Confirm(cA). R verifies: failure -> `Codes.Fail()`; attempts left > 0 -> R -> I
   PairResult{accepted: false, reason: wrongCode} and the loop restarts with new ephemeral scalars; 0 left ->
   PairResult tooManyAttempts and close. Success -> R -> I Spake2Confirm(cB); I verifies (failure -> I sends
   PairResult wrongCode and fails: this only happens under MITM because R already verified cA); I -> R
   PairResult{accepted: true}; I returns Result. R calls `Codes.Consume()` and returns Result only after receiving
   that PairResult.
5. Nothing is stored here: the caller stores the returned Result (peer store) - so no pin exists before both
   confirmations (security checklist 1).
6. Timeouts: protocol reads 10 s each; waits that include user input (I waiting for `Code`, R waiting for the next
   Spake2Share) are bounded by the code expiry. Every failure the peer sees is a PairResult with `wrongCode`,
   `expired`, `tooManyAttempts`, `cancelled` or `internal`; internal errors are never described to the peer.
7. `TestPair_ExporterMismatchFails`: give the two sides different `aad` (simulated MITM with two TLS sessions) and
   assert confirmation fails with the correct code.

## Item P1-C2-009
`internal/peers` package doc: "Package peers stores paired machines: pins, names and network info (peers.toml)."
```go
type Peer struct {
    ID peerid.ID; Name, OS string; Role msg.Role
    MACs []net.HardwareAddr; Broadcast []netip.Addr; Addresses []string // last known "host:port", newest first, max 8
    PairedAt time.Time
}
type Store struct{ ... }
func Open(path string) (*Store, error)               // missing file -> empty store; strict decode (DisallowUnknownFields)
func (s *Store) Add(p Peer) error                    // replace same ID; persists
func (s *Store) Get(id peerid.ID) (Peer, bool)
func (s *Store) List() []Peer                        // sorted by Name, then ID
func (s *Store) Rename(id peerid.ID, name string) error
func (s *Store) Remove(id peerid.ID) error           // unpair: the pin disappears immediately
func (s *Store) SetNetInfo(id peerid.ID, macs []net.HardwareAddr, bc []netip.Addr, addr string) error
func (s *Store) IsPinned(id peerid.ID) bool          // implements pki.PinStore
func (s *Store) Subscribe() (<-chan struct{}, func()) // coalesced change signal (buffer 1)
var ErrNotFound = ...
```
TOML layout: `schema_version = 1` then `[[peer]]` tables with keys `id, name, os, role, macs, broadcast, addresses,
paired_at` (RFC 3339). Names: trimmed, 1..64 bytes, no control chars (`ErrInvalidName`); default name when the
caller passes an empty name = the peer's advertised name (PairHello.Name, which defaults to its hostname).
Atomic persist on every mutation; all methods safe for concurrent use.
