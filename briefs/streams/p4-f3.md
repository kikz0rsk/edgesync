# Stream brief - P4 F3 macOS file paste, drag-and-drop and GUI drop (compile + CI only)

Phase 4 stream. Items: `briefs/plan-phase-4.md` section "F3". Owner tag `[owner:F3]`.

## Scope
Implement `platform.FileClipboard` (FEAT-107) and `platform.DragDrop` (FEAT-108) for macOS with purego in the
agent (`CGO_ENABLED=0`, D-34, D-39), and native file drop onto the Gio window (FEAT-109) with cgo Objective-C in
the GUI.

Nobody can run this on a Mac by hand (R-07). Evidence comes from:
- cross-compiling on the Windows host (`GOOS=darwin GOARCH=arm64|amd64 CGO_ENABLED=0`);
- the macOS integration job on `macos-latest`, which the user dispatches after pushing.

Every report states the evidence level per behaviour: CI-verified, compile-only, or unverifiable.

## Conventions (binding)
- **Decisions:** D-11, D-12, D-13, D-34, D-39, D-45, D-48, D-61, D-62, and the P4-F3-001 decision.
- **purego and AppKit:**
  - `github.com/ebitengine/purego` v0.11.2 with `purego/objc`.
  - Class registration via `objc.RegisterClass` with the protocol methods below; one class per role, registered once (guarded by `sync.Once` owned by the backend struct, not package state).
  - All AppKit object creation and pasteboard writes run on the AppKit main thread through M1's dispatcher.
  - Promise file writes run on a private `NSOperationQueue` returned from `operationQueueForFilePromiseProvider:`, never on the main thread.
- **Objective-C blocks handed to us by AppKit** (`completionHandler`) are invoked through the block ABI. Block literal layout: `isa` ptr (0), `flags` int32 (8), `reserved` int32 (12), `invoke` fn ptr (16), `descriptor` ptr (24). Call `invoke(block, arg)` with `purego.SyscallN`. Verify against the clang Blocks ABI document and record the source. Each completion handler is called exactly once.
- **Pasteboard privacy (R-15):** poll only `changeCount` and `types` for change detection. Read file URLs only when the P4-F3-001 decision allows reading at copy time; otherwise follow that decision's deferred-read rule.
- **GUI drop** uses cgo Objective-C (`drop_darwin.m`, `#cgo CFLAGS: -x objective-c`, `#cgo LDFLAGS: -framework AppKit`), allowed for the GUI by D-34 and confirmed at P4-F-002.
- **Integration tests:** `//go:build integration && darwin`. Each test logs `AXIsProcessTrusted` and its evidence level.
- No em dashes or en dashes. Commits `feat(macos): ...` / `feat(gui): ...`, body `Item: <id>`, no attribution trailers.

## Item P4-F3-003
- `vfile/writer.go` (build-tag free, host-tested): `type PromiseWriter` with `Write(ctx, dir string, m vfile.Manifest, top int, p vfile.Provider) (string, error)`.
  - Opens an `os.Root` on `dir` (the destination folder Finder gives) and writes the top-level entry and its descendants through the P1 C4 receive writer (partial file, per-chunk verify, rename).
  - A name clash in `dir` gets the ` (n)` suffix (D-17).
  - Unsafe names fail before IO.
  - Returns the final name.
- `vfile/promise_darwin.go`: registers class `EdgeSyncFilePromiseDelegate` (NSObject, protocol `NSFilePromiseProviderDelegate`):
  - `filePromiseProvider:fileNameForType:` returns the top-level entry name (validated).
  - `filePromiseProvider:writePromiseToURL:completionHandler:` takes the URL's parent directory as `dir` and the last component as the name, runs `PromiseWriter.Write` for that top-level index, then invokes the completion handler with nil or an `NSError` (domain `io.github.kikz0r.edgesync`, code 1, localized description from i18n `files.pasteFailed`).
  - `operationQueueForFilePromiseProvider:` returns a serial queue owned by the FileClipboard.
  - The delegate instance maps provider -> (manifest, top index, provider) through a handle table.
  - After every top-level promise completed, call `Done(OutcomeCompleted)`; any failure gives `Done(OutcomeFailed)`.

## Item P4-F3-004
`vfile/fileclipboard_darwin.go`:
- **WatchFiles:**
  - Poll `generalPasteboard.changeCount` on M1's dispatcher at M1's clipboard poll interval (NOTE from P4-F-001).
  - When it changed and the change is not ours (we record the changeCount after each of our writes), check `types`. If `public.file-url` is present (the concealed type is not special-cased, D-121), read the URLs with `readObjectsForClasses:@[NSURL] options:@{FileURLsOnly: YES}` (subject to the R-15 decision) and call `fn(changeCount, paths)`.
- **OfferFiles:**
  - Build one `NSFilePromiseProvider` per top-level entry (`public.folder` for directories, `public.data` for files) with the delegate.
  - On the main thread: `clearContents`, `writeObjects:`, record the changeCount.
  - The previous offer's provider gets Abandoned unless it has an outcome.
- **Close:** if `changeCount` still equals our last write, call `clearContents`. Release objects.

## Item P4-F3-006
- `dnd/geometry.go` (host-tested): converts EdgeSegments (physical pixels, top-left origin per D-51) to strip rects in AppKit screen points:
  - divide by the monitor's scale;
  - flip y with the primary screen height (Cocoa origin is bottom-left);
  - 2 points thick inside the monitor.
- `dnd/edge_darwin.go`:
  - Registers class `EdgeSyncDropView` (NSView, NSDraggingDestination):
    - `draggingEntered:`: read file URLs from `draggingPasteboard`. With file URLs, emit `DragOutEnter` and return Copy; without, emit `DragOutUnsupported` and return None.
    - `draggingUpdated:` returns the same as entered.
    - `draggingExited:` emits `DragOutLeave`.
    - `prepareForDragOperation:` returns YES only for an accepted drag.
    - `performDragOperation:` returns the pending remote outcome (P4-F3-007) or emits `DragOutDrop` and returns NO.
  - One borderless non-activating `NSPanel` per strip at status-window level, all spaces, transparent, with `EdgeSyncDropView` as content view registered for `public.file-url`.
  - `Arm(true)`: `setIgnoresMouseEvents:NO`. `Arm(false)`: YES.
- `dnd/dragdrop_darwin.go`: the `DragDrop` type with fan-out and state.

## Item P4-F3-007
`dnd/finish_darwin.go`. Same semantics as Windows:
- accepted: set the pending outcome to accept and post a left-mouse-up `CGEvent` (M1's synthetic marker in `kCGEventSourceUserData`) at the current location over the strip, so Finder's drag session ends with our `performDragOperation:` returning YES;
- not accepted: set the pending outcome to refuse and post Escape key down/up.

Idempotent; 2 s confirmation timeout with a typed error.

## Item P4-F3-008
`dnd/incoming_darwin.go`. `BeginIncoming` registers class `EdgeSyncDragSourceView` (NSView, NSDraggingSource):
- `draggingSession:sourceOperationMaskForDraggingContext:` returns Copy.
- `draggingSession:endedAtPoint:operation:` records the result: Dropped = operation == Copy.
- `mouseDown:` records the event.
- `mouseDragged:` on the first call runs `beginDraggingSessionWithItems:event:source:`. Items are one `NSDraggingItem` per top-level entry, whose pasteboard writer is an `NSFilePromiseProvider` with the F3 delegate, and whose dragging frame is a 32x32 rect at the view centre.

Sequence:
1. On the main thread, create a 32x32 transparent panel at `at` (converted to points) with that view.
2. Post (marked) left-mouse-down at `at`, then a left-mouse-dragged 4 points away, so AppKit delivers `mouseDown:`/`mouseDragged:` to our view.
3. `Release()` posts a marked left-mouse-up at the current location. `Cancel()` posts Escape.
4. `Wait` returns after `endedAtPoint`. Close the panel.

Without TCC on CI the events may not post. The integration test logs the trust state and evidence level.
