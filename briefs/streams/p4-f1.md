# Stream brief - P4 F1 Windows virtual-file paste

Phase 4 stream. Items: `briefs/plan-phase-4.md` section "F1". Owner tag `[owner:F1]`.

## Scope
Implement `platform.FileClipboard` for Windows (FEAT-103, D-11).
- **Copy side:** a local file copy (CF_HDROP) is detected and reported.
- **Paste side:** a remote manifest is placed on the clipboard as an OLE `IDataObject` exposing `FileGroupDescriptorW` + `FileContents` (IStream per file). Explorer pastes it with its own progress UI, pulling bytes through `vfile.Provider`.
- Includes the COM objects needed for this (IDataObject, IEnumFORMATETC, IStream), integration tests on CI, and the manual script for the two Windows PCs.

## Conventions (binding)
- **Decisions:** D-11, D-13, D-39, D-44, D-45, D-48, D-61, D-62, D-64, D-75, and the P4-F-002 decisions (Windows name rules, read-ahead window, manifest limits).
- **Pure Go, `CGO_ENABLED=0`:**
  - `golang.org/x/sys/windows` plus own `LazyDLL` declarations;
  - COM objects built by hand following the SP2-proven pattern (`briefs/spikes/sp2.md`, "Recommended design for P2 W2 and P4 F1/F2");
  - no go-ole.
- **COM memory rules (R-24):**
  - Object blocks and vtables live outside the Go heap (`windows.LocalAlloc(LMEM_FIXED|LMEM_ZEROINIT, n)` or `CoTaskMemAlloc`).
  - Layout per object: `{ lpVtbl uintptr; handle uintptr }`. The handle indexes a mutex-protected Go table holding the implementation and the reference count.
  - One `syscall.NewCallback` per interface method, created once and shared by all instances. The package asserts in a test that the total stays <= 64.
  - Never give Windows a pointer into the Go heap to keep.
- **Threading:**
  - All OLE calls run on one STA thread per FileClipboard (`runtime.LockOSThread`, `OleInitialize(nil)`, `GetMessageW` pump, work queue), using W2's `com.STA` if it exists (P4-F-001 NOTE).
  - Calls from Explorer arrive marshalled on this STA. Method implementations must not block it for longer than one read-ahead wait.
  - Follow sp2.md row "blocking behaviour" for the threading model: STA with read-ahead (default), or aggregating the free-threaded marshaler (`CoCreateFreeThreadedMarshaler`) for IStream objects if sp2.md recommends it. Anything else: STOP and report BLOCKED.
- **Verify every constant and layout against Microsoft Learn / Windows SDK headers before use.** Values below are the expected ones; a mismatch is BLOCKED.
- **Integration tests:** `//go:build integration && windows`. Never run on the host; vet them with `go vet -tags integration ./internal/platform/windows/...`.
- No em dashes or en dashes. Commit `feat(win): ... [FEAT-103]`, body `Item: <id>`, no attribution trailers.

## Item P4-F1-002
Only when the P4-F-001 NOTE says W2 has no IDataObject/IEnumFORMATETC.
- `com/dataobject_windows.go`: `type DataSource interface { Formats() []FORMATETC; GetData(f *FORMATETC) (STGMEDIUM, HRESULT); QueryGetData(f *FORMATETC) HRESULT; SetData(f *FORMATETC, m *STGMEDIUM, release bool) HRESULT }` and `func NewDataObject(src DataSource, extraIIDs ...) (*Object, error)`.
- `GetDataHere` returns E_NOTIMPL. `GetCanonicalFormatEtc` copies in to out with `ptd=0` and returns DATA_S_SAMEFORMATETC. The advise methods return OLE_E_ADVISENOTSUPPORTED.
- `QueryInterface` answers IUnknown and IDataObject (plus extra IIDs registered by later items, P4-F2-004). `Release` at zero frees the object block and the handle, then calls `src` cleanup.
- `com/enumformatetc_windows.go`: an enumerator over a copied slice: Next fills up to celt and returns S_FALSE when fewer, Skip, Reset, Clone.
- Tests call through the vtables with `syscall.SyscallN`.

## Item P4-F1-003
`com/stream_windows.go`: `type StreamSource interface { Read(p []byte) (int, error); Seek(off int64, whence int) (int64, error); Size() int64; Name() string; Close() error }` and `func NewStream(src StreamSource) (*Object, error)`.
- **Read:** loop until `cb` bytes or EOF. Write `*pcbRead` when non-nil. At EOF with fewer bytes, return S_OK with the short count (verify against the `ISequentialStream::Read` docs and record the exact rule followed). A source error returns STG_E_READFAULT and is logged at Warn without names.
- **Seek:** maps STREAM_SEEK_* to io.Seek* and writes the new position. A negative result gives STG_E_INVALIDFUNCTION.
- **Stat:** fills `cbSize` and `type=STGTY_STREAM`. With STATFLAG_DEFAULT it allocates `pwcsName` with `CoTaskMemAlloc` (UTF-16, NUL-terminated); with STATFLAG_NONAME it leaves it 0.
- **Other methods:** Write gives STG_E_ACCESSDENIED. SetSize, CopyTo, Commit, Revert, LockRegion, UnlockRegion and Clone return STG_E_INVALIDFUNCTION, except Commit (S_OK, no-op on a read-only stream; verify the documented expectation).
- QueryInterface answers IUnknown, ISequentialStream and IStream. `Release` at zero calls `src.Close()`.

## Item P4-F1-004
`vfile/descriptor_windows.go`: `func BuildGroupDescriptor(m vfile.Manifest) ([]byte, error)` returns the raw FILEGROUPDESCRIPTORW bytes. The data source copies them into an HGLOBAL.
- Path: "/" becomes "\". UTF-16 length <= 259 code units, else `vfile.ErrNotRepresentable` wrapping the index.
- Each component is checked against Microsoft "Naming Files" rules:
  - none of `<>:"|?*`, no control characters < 0x20;
  - not a reserved device name (CON, PRN, AUX, NUL, COM1-9, LPT1-9, with or without extension);
  - no trailing dot or space.

  The ':' rule blocks alternate data streams.
- Fields:
  - `dwFlags = FD_ATTRIBUTES|FD_FILESIZE|FD_WRITESTIME|FD_PROGRESSUI|FD_UNICODE`;
  - `dwFileAttributes` = DIRECTORY or NORMAL;
  - `ftLastWriteTime` from ModTime;
  - size split into high/low;
  - `cFileName` NUL-terminated.
- Golden-bytes test: two entries (folder `a`, file `a/b.txt` of 5 bytes, fixed ModTime).

## Item P4-F1-005
`vfile/datasource_windows.go`: `func NewDataSource(m vfile.Manifest, p vfile.Provider, opts DataSourceOptions) (com.DataSource, error)`. Options: read-ahead window (decision from P4-F-002) and the async-capability flag added later by P4-F2-004.

Formats, in this order:
1. `FileGroupDescriptorW` (TYMED_HGLOBAL, lindex -1): the descriptor is built once at construction; construction fails with `ErrNotRepresentable` before anything reaches the clipboard.
2. `FileContents` (TYMED_ISTREAM, lindex = descriptor index):
   - a directory or out-of-range lindex gives DV_E_LINDEX;
   - each GetData returns a new IStream over `vfile.NewReadAhead(ctx, p, lindex, size, window)`;
   - at most 4 streams open at once (D-44): a fifth GetData waits for a free slot on the STA-safe semaphore up to the clipboard fetch timeout (D-57), then returns E_FAIL.
3. `Preferred DropEffect` (TYMED_HGLOBAL, DWORD): always DROPEFFECT_COPY (D-62).

Validation rules:
- QueryGetData checks format, tymed and aspect (DVASPECT_CONTENT only) and returns DV_E_FORMATETC, DV_E_TYMED or DV_E_DVASPECT respectively.
- SetData accepts `Performed DropEffect`, `Logical Performed DropEffect` and `Paste Succeeded`:
  - MOVE is treated exactly like COPY (D-62);
  - `Paste Succeeded` gives `p.Done(OutcomeCompleted)`;
  - a performed effect of NONE gives `Done(OutcomeCancelled)`;
  - every other format gives E_NOTIMPL;
  - `fRelease` is honoured.
- When the data object's last reference goes away without an outcome: `Done(OutcomeAbandoned)`.

Tests run through the vtables with a fake provider.

## Item P4-F1-006
`vfile/fileclipboard_windows.go`: `func NewFileClipboard(log *slog.Logger, opts Options) (platform.FileClipboard, error)`. Own STA (or `com.STA`), plus a message-only window on it registered with `AddClipboardFormatListener`.
- **WatchFiles**, on `WM_CLIPBOARDUPDATE`:
  1. `seq := GetClipboardSequenceNumber()`. If `seq == lastOwnSeq` or `OleIsCurrentClipboard(current) == S_OK`, ignore.
  2. If CF_HDROP is not available, ignore.
  3. No sensitivity check (D-121): `ExcludeClipboardContentFromMonitorProcessing` and `CanIncludeInClipboardHistory` are not interpreted.
  4. `OpenClipboard(hwnd)`. On failure retry up to 5 times at 20 ms intervals, then log Warn and drop this change.
  5. `GetClipboardData(CF_HDROP)`, then `DragQueryFileW(h, 0xFFFFFFFF)` for the count and each path into a buffer sized by the query. `CloseClipboard`.
  6. `fn(uint64(seq), paths)`. `Preferred DropEffect` MOVE (cut) is ignored (D-62).
- `hdrop_windows.go`: `ParseDROPFILES(b []byte) ([]string, error)` for the byte-level form used by tests and by P4-F2-003. `fWide` must be 1; the list is double-NUL terminated.
- **OfferFiles**, on the STA:
  1. Build the data source (`ErrNotRepresentable` is returned unchanged).
  2. Create the data object, `OleSetClipboard(obj)`.
  3. Remember `lastOwnSeq = GetClipboardSequenceNumber()`.
  4. Release our extra reference. OLE now owns one; the previous offer is released by OLE, so its provider gets Abandoned unless it has an outcome.
- **Close:** if `OleIsCurrentClipboard(obj) == S_OK`, call `OleSetClipboard(0)`. Never `OleFlushClipboard`, because flushing would try to render every file's contents. Then `RemoveClipboardFormatListener`, destroy the window and stop the STA.

## Item P4-F1-009
`qa/manual/p4-f1-virtual-files.md` per `qa/manual/README.md`. Machines: Windows PC 1 (server), Windows PC 2 (client), wired.

Steps, each with expected observation and paste-back:
1. Copy a single 4 GiB file on PC1, paste in Explorer on PC2. Record:
   - Explorer progress UI;
   - total time;
   - agent log stats line (TTFB, bytes, duration) for PB-11 and PB-25;
   - agent RSS from Task Manager during the copy (PB-17);
   - SHA-256 on both sides (`certutil -hashfile`).
2. 10 000 x 4 KiB files in one folder (generator command given in the script).
3. A folder nested 10 levels with empty directories.
4. Unicode names (Slovak diacritics, CJK, emoji).
5. Name clash: paste twice into the same folder; Explorer's own replace/skip/rename dialog appears.
6. Cancel in Explorer's progress dialog mid-paste: the queue entry shows cancelled, no partial file remains.
7. Peer disconnect mid-paste (unplug PC1's cable for 10 s): Explorer shows an error with retry; after reconnect, Retry completes and the hash matches.
8. Supersede: after copying files on PC1, copy text on PC1, then paste on PC2. Text is pasted, no file paste is offered.
9. Cut on PC1 (Ctrl+X), paste on PC2: PC1's files still exist (D-62).
10. Path longer than 259 characters: notification `files.notRepresentable`, nothing on the clipboard.
11. Paste into an Explorer window running as administrator.
12. Paste on PC2 after the PC1 agent quit: the clipboard no longer offers the files.
13. Copy on PC2 (client), paste on PC1 (server).

Cleanup and safety sections as required.
