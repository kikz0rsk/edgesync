## Scope
The Windows clipboard backend with delayed rendering (D-10, D-40, D-61); the production pure-Go COM package that
P4 F1/F2 build virtual files and drag-and-drop on (from SP2); `edgesync-service` (LocalSystem): session tracking,
secure-helper launch and supervision, the authorised service pipe (D-47), the machine identity and TLS signing
proxy (D-41), `SendSAS`; the secure helper (`edgesync-agent --secure-helper`): desktop following, helper-routed
injection (UIPI-free), secure-desktop capture forwarding and pre-login client mode (D-63, D-64). Security-critical
stream: the security-review gate is mandatory (P2-W2-034).

## Item P2-W2-001
`w2_clipboard.go` (user32): OpenClipboard, CloseClipboard, EmptyClipboard, GetClipboardData, SetClipboardData,

WM_RENDERALLFORMATS 0x0306, WM_DESTROYCLIPBOARD 0x0307. Tests: procs resolve; constants table.

## Item P2-W2-002
`formats.go` (untagged): canonical -> native list in offer order: FormatText -> CF_UNICODETEXT; FormatHTML ->
registered "HTML Format"; FormatRTF -> registered "Rich Text Format"; FormatPNG -> registered "PNG" then CF_DIBV5
(Windows synthesises CF_DIB/CF_BITMAP). Native -> canonical: prefer "PNG" over CF_DIBV5 over CF_DIB for FormatPNG.
Registered IDs are resolved at runtime by the windows file and passed in, so the table is testable on the host.
No sensitivity detection (D-121): the registered formats "ExcludeClipboardContentFromMonitorProcessing" and "CanIncludeInClipboardHistory" are not
interpreted; content that carries them is announced like any other content.
`native.go` (untagged): UTF-8 -> UTF-16LE with terminating NUL and back (odd byte count = error, stop at the first
NUL); CF_HTML and DIB/DIBV5 <-> PNG via `internal/clipboard/convert` (read its exported functions; a missing one =
BLOCKED, the package is C4's).

## Item P2-W2-003
`window_windows.go`: the clipboard owns a dedicated `msgloop.Thread` ("edgesync-clipboard") with a message-only
window (clipboard listeners and owners work with message-only windows; sp2.md confirms) - never the hook thread,
because rendering blocks. `watch_windows.go`: `AddClipboardFormatListener(hwnd)`; on WM_CLIPBOARDUPDATE: read
`GetClipboardSequenceNumber`, skip if unchanged since the last report; `GetClipboardOwner() == hwnd` -> our own offer,
skip; open (retry policy), enumerate formats (`EnumClipboardFormats`, names via `GetClipboardFormatNameW` for IDs
>= 0xC000), close without reading any data (D-121: no sensitivity detection);
report `LocalChange{Seq: backend counter, Formats (Size -1)}`. Do not read content in Watch (sizes stay
-1). `retry.go`: OpenClipboard retry policy 10 attempts x 20 ms, then `ErrClipboardBusy` naming the owner window's
class (synctest).

## Item P2-W2-004
Forward requirement (D-102): an update whose only formats are virtual-file formats (`FileGroupDescriptorW` / `FileContents` without `CF_HDROP`) is never announced; test `TestRead_VirtualOnlyUpdateNotAnnounced` (integration file) and the pure format-table check in P2-W2-002.
`read_windows.go`: `Read(ctx, f, w)`: open with retry, `GetClipboardData(native)`, `GlobalLock`, copy
`GlobalSize` bytes, unlock, close, then convert: text UTF-16 -> UTF-8 -> `convert` normalisation; HTML from CF_HTML
fragment via `convert`; RTF raw; PNG from "PNG" if present else DIBV5/DIB via `convert`. Missing native format ->
`ErrFormatUnavailable` (sentinel, wraps the format). Enforce the 64 MiB cap (D-57) before copying (`ErrTooLarge`).
Integration tests place eager data from a test-owned window on another thread.

## Item P2-W2-005
Offer (sonnet). `offer_windows.go`: `Offer(ctx, formats, p)` runs on the clipboard thread: `OpenClipboard(hwnd)`,
`EmptyClipboard`, for each canonical format `SetClipboardData(native, 0)` (delayed), `CloseClipboard`; store
`{seq, formats, provider}`. `render_windows.go`:
- WM_RENDERFORMAT(native): find the canonical format; `ctx` with the D-57 fetch timeout (10 s for <= 1 MiB, else
  10 s + 1 s per started MiB; size unknown -> 10 s); `p.Render(ctx, f, buf)`; convert to native; `GlobalAlloc
  (GMEM_MOVEABLE)`, copy, `SetClipboardData(native, h)` WITHOUT opening the clipboard (Microsoft rule). On provider
  error or timeout: do not call SetClipboardData (the pasting app gets nothing), log Warn with format and reason
  (never content). Each format renders at most once per offer.
- WM_RENDERALLFORMATS (agent exiting while owner): `OpenClipboard(hwnd)`; if `GetClipboardOwner() != hwnd` close and
  return; render every not-yet-rendered format with the same timeouts; failures logged individually; close.
- WM_DESTROYCLIPBOARD: drop the stored provider (ownership lost).
- `Close` of the backend destroys the window, which triggers WM_RENDERALLFORMATS first (document the order).

## Item P2-W2-023
Brokered helper channel (sonnet, G-04). Helper side (`helper/pipe_windows.go`): the helper listens on
`\\.\pipe\edgesync-helper-<session>` with SDDL `D:P(A;;GA;;;SY)` (SYSTEM only) and first-instance semantics; it
accepts a connection only after the service's control message on the separate helper<->service control pipe (also
SYSTEM-only) announced a pending broker ticket (random 128-bit) that the new client presents first. Service side
(`broker_windows.go`): on an authorised `Hello` from the agent of the helper's session, open the helper pipe as
SYSTEM, present the ticket, then `DuplicateHandle(GetCurrentProcess(), pipeHandle, agentProcessHandle, &dup, 0,
false, DUPLICATE_SAME_ACCESS)` into the agent (agent process opened with `PROCESS_DUP_HANDLE`), close the service's
copy, return `dup` (the numeric handle value in the agent process) in the Hello response. The agent wraps it with
`os.NewFile` + `net.FileConn` (Go 1.25+ supports this on Windows for overlapped handles; verify; if it does not work
for pipe handles, BLOCKED with details).

## Item P2-W2-036
D-112. Package `internal/service/machinepeers` (package doc: machine-scoped peer store for pre-login mode). File `%ProgramData%\EdgeSync\machine-peers.toml` (the path is assembled by the callers from `internal/paths`; the store takes the file path).
```go
type Peer struct { ID string; Name string; AddedAt time.Time }
type Store struct{ /* path, mutex */ }
func Open(path string) *Store
func (s *Store) Load() ([]Peer, error)             // absent file = empty list; strict decode (go-toml/v2 DisallowUnknownFields); schema_version must be 1
func (s *Store) Contains(id string) (bool, error)  // re-reads the file on every call (no cache): a change applies to the next session
func (s *Store) Add(p Peer) error                  // idempotent (same ID updates the name), sorted by ID, atomic write (temp file + fsync + rename in the same directory, the P1-C5-002 helper)
func (s *Store) Remove(id string) error            // absent ID is not an error
func ValidID(id string) bool                       // exactly 52 characters of the lowercase RFC 4648 base32 alphabet a-z2-7 (D-42)
```
TOML: `schema_version = 1` and `[[peer]]` tables with `id`, `name`, `added_at` (RFC 3339). `name` at most 64 bytes without control characters, `id` validated by `ValidID` on every load and add. Callers are serialised by a mutex; in production the elevated command (P2-W2-037) is the only writer and the service (P2-W2-028, P2-W2-038) only reads. The package has no dependency on the Windows API (the ACL is applied by the callers), so its tests run on every OS.
