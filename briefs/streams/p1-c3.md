# Stream brief - P1 C3 Layout, engine and keymap

Phase 1 core stream. Items: `briefs/plan-phase-1.md` section "C3". Owner tag: `[owner:C3]`. Starts after the
CONTRACT FREEZE (P1-F-022).

## Scope
The physical-key tables (generated from Chromium's BSD-licensed DOM code table), key names and modifier remap, the
free-form layout geometry (canvas, real edges, adjacency, crossing mapping, validation, snapping), and the input
engine: key state, hotkeys, the four edge guards, the server engine (switching, virtual cursor, coalescing, hotkey
actions, failure handling) and the client engine. Pure logic over the frozen platform interfaces and fakes; no
network code (the engine talks to a consumer-defined `Sender`).

## Owned paths
`internal/keymap/**` (except the frozen `usage.go`), `internal/layout/**`, `internal/engine/**`,
`third_party/chromium/**`.
Leave alone: `internal/keymap/usage.go`, `internal/platform/**`, `internal/proto/**`, `internal/session/**`.

## Conventions (binding)
- Decisions: D-04, D-05, D-06, D-08, D-27, D-30, D-49, D-51, D-57, D-58, D-67, D-70, D-75, D-76.
- Hot path (capture event -> frame queued, client frame -> injector call) performs zero heap allocations: fixed
  arrays, preallocated buffers, no interfaces boxed per event, no `fmt` on the hot path. Benchmarks assert it.
- Engines own one goroutine each (`Run(ctx)`); every external call is a command sent to that goroutine (channel with
  a reply channel where a result is needed). No locks shared with the loop's state.
- All timing via `time.Now`/`time.NewTimer` inside `testing/synctest` bubbles in tests; no injected clocks.
- Canvas math in float64; physical coordinates int32; rounding with `math.Round` and explicit clamping.
- Clean-room rule (D-27): no code or tables from Deskflow, Barrier, Input Leap, Synergy, lan-mouse.
- No em dashes or en dashes. Commit scopes: `keymap`, `layout`, `engine`.

## Item P1-C3-005
`internal/layout` package doc: "Package layout models the free-form arrangement of machines and computes real
edges, adjacency and crossing points (D-04, D-51)."
```go
type Machine struct { ID peerid.ID; Name string; Origin platform.Point /* canvas, logical units */; Desktop platform.Desktop; Online bool }
type Layout struct { Version uint64; Machines []Machine }
func (l Layout) Machine(id peerid.ID) (Machine, bool)
func FromConfig(c config.Layout) (Layout, error)       // peer ids parsed; invalid id -> error
func (l Layout) ToConfig() config.Layout
func FromSnapshot(s msg.LayoutSnapshot) Layout
func (l Layout) ToSnapshot() msg.LayoutSnapshot
type CanvasRect struct { X, Y, W, H float64 }
func MonitorCanvasRect(m Machine, i int) CanvasRect      // monitor index i of m.Desktop
func MachineCanvasBounds(m Machine) CanvasRect
```
Canvas formulas (D-51): let (minX, minY) = the minimum physical X and Y over the machine's monitors; reference scale
r = primary monitor `ScalePermille / 1000` (first monitor when none is primary); monitor scale s =
`ScalePermille / 1000`. Monitor canvas rect: X = Origin.X + (mon.X - minX) / r, Y = Origin.Y + (mon.Y - minY) / r,
W = mon.W / s, H = mon.H / s. Small gaps or overlaps between a machine's own monitors on the canvas are cosmetic;
internal edges are decided physically (P1-C3-006). ScalePermille 0 is invalid (validation, P1-C3-008).

## Item P1-C3-006
```go
func RealEdges(d platform.Desktop) []platform.EdgeSegment // IDs zero here; physical coordinates
```
For each monitor side, start with the full side interval and subtract every interval covered by another monitor of
the same desktop that touches that side exactly (for the right side of A: monitors B with B.X == A.Right(); covered
interval = [max(A.Y, B.Y), min(A.Bottom(), B.Bottom())) when non-empty; analogous for the other sides). Remaining
non-empty intervals are real edges: `EdgeSegment{Monitor: mon.ID, Side, From, To, At}` with `At` = A.Right() for
Right, A.X for Left, A.Y for Top, A.Bottom() for Bottom. Order: monitor index, then side (Left, Right, Top,
Bottom), then From. Port and extend the spike's tests (`spikes/wininject/edges_test.go`).

## Item P1-C3-007
`adjacency.go`, `mapping.go`:
```go
type Graph struct{ ... }                                   // immutable, built per layout
func Build(l Layout) (*Graph, error)
func (g *Graph) Edges(id peerid.ID) []platform.EdgeSegment // only segments with a facing neighbour; IDs 1..n unique per machine, deterministic
func (g *Graph) Neighbour(id peerid.ID, edge uint16) (peerid.ID, bool)
func (g *Graph) Map(from peerid.ID, edge uint16, p platform.Point) (to peerid.ID, entry platform.Point, err error)
func (g *Graph) Exit(id peerid.ID, from, to platform.Point) (edge uint16, contact platform.Point, ok bool)
func (g *Graph) Clamp(id peerid.ID, from, to platform.Point) platform.Point
var (ErrUnknownEdge, ErrWall, ErrUnknownMachine = ...)
```
- Canvas segment of a real edge of monitor mon (rect c, scale s): vertical sides (Left/Right) lie on x = c.X or
  c.X + c.W, along y from c.Y + (From - mon.Y)/s to c.Y + (To - mon.Y)/s; horizontal sides analogously.
- Facing: Right faces Left, Bottom faces Top (and vice versa) of another machine when the lines are within 2.0
  logical units; overlap = intersection of the along intervals, kept when longer than 0.5 units. `Edges` splits each
  real edge into the physical sub-intervals that overlap a facing neighbour edge (convert canvas back with the
  source scale; round outward to whole pixels; drop empty).
- Map: along coordinate t of p on the source (vertical sides: t = c.Y + (p.Y - mon.Y)/s); find the link containing
  t (half-open); in the target monitor (rect tc, scale ts): along = tm.Y + round((t - tc.Y) * ts) clamped to
  [tm.Y, tm.Bottom()-1]; perpendicular: entering through the target's Left side -> x = tm.X, Right -> tm.Right()-1,
  Top -> y = tm.Y, Bottom -> tm.Bottom()-1. t outside every link -> ErrWall.
- Exit (virtual cursor on a client): if `to` is inside some monitor of the machine -> ok=false (no exit). Otherwise
  take the monitor containing `from`, compute where the segment from->to leaves it (first side crossed, parametric),
  and if that point lies on one of `Edges(id)` return its ID and the contact point; else ok=false (wall).
- Clamp: `to` inside a monitor -> `to`; else clamp into the monitor containing `from`.
- Offline neighbours are still linked (the engine decides wall vs wake, P1-C3-016).

## Item P1-C3-008

threshold (corner alignment). Port the spike's snap tests.

## Item P1-C3-012
`guard_dwell.go`: first contact on an edge records (edge ID, time) and returns Pending until time + delay (default
150 ms, D-57); a later Evaluate on the same edge at or after that time returns Allow; `Motion` with distance > 0
(pointer left the edge line) resets; a contact on a different edge restarts. Disabled guard is simply absent from
the set. `BenchmarkDwellEvaluate` with `b.ReportAllocs()` must show 0 allocs/op.

## Item P1-C3-013
`guard_doubletap.go`: first contact -> Deny and arm (edge ID, time t1, `movedAway = false`); `Motion` with distance
>= MinMovePX (default 8 logical px, D-57) sets movedAway; a contact on the same edge with movedAway and time - t1 <=
window (400 ms) -> Allow and disarm; window expired -> treat as a new first contact; different edge -> re-arm.

## Item P1-C3-014
`guard_corner.go`: let `size` = SizePX (default 32) converted to physical px with `ScalePermille`
(size * scale / 1000, rounded); along coordinate a of the contact (Y for vertical sides, X for horizontal); Deny
when a - From < size or To - 1 - a < size, else Allow. A segment shorter than 2*size is entirely dead.

## Item P1-C3-015
Planning consolidation (D-90): the server answers every `KindEdgeContact` received while not grabbed with exactly one `Grab` or `Ungrab(contact point)`. When the capturer implements `platform.ContactHolder` and `HoldsContact()` is true: modifier and corner guards decide at once; the dwell guard holds for min(dwell, 400 ms); the double-tap guard ungrabs the first contact and grabs on the second. ## Item P1-C3-017
`coalesce.go`: `type coalescer` used by the server loop: a motion for the active client is sent immediately when
>= 1 ms has passed since the last motion send, otherwise kept as pending (latest wins) with one timer armed for
lastSend + 1 ms. Before any Button frame, the pending or latest unsent position goes on the reliable input stream so
clicks land where the cursor is; Key and Wheel frames flush pending motion via the datagram path first. Seq
increments per motion frame sent. `TestCoalescing1000Hz`: 10 s of 1000 Hz synthetic motion with jitter in a
synctest bubble -> <= 1000 MotionAbs per second and no pending motion older than 2 ms (PB-06).

## Item P1-C3-026
D-113. `server_sendcad.go`:
```go
var ErrSendCADUnavailable = errors.New("engine: Send Ctrl+Alt+Del unavailable")   // wrapped with the reason
func (s *Server) SendCtrlAltDel(peer peerid.ID) error
```
The peer must be online and its `Hello` must report `os == "windows"` and `capabilities.secureDesktop == true` (read through the same peer-facts accessor the engine already uses for the layout; `os` is expected to carry `runtime.GOOS` of the peer, verify the value the handshake code in P1-C1 writes; `secureDesktop` is populated by the agent in P3-G5-021, so until then the engine treats an absent capability as unavailable); otherwise `ErrSendCADUnavailable` with the reason and an event for the agent to show as a notification. When `peer` is not the active machine, `JumpTo(peer)` (P1-C3-018, guards skipped) runs first. The chord goes out through the normal forwarding path as reliable key events in this order: ControlLeft down, AltLeft down, Delete down, Delete up, AltLeft up, ControlLeft up (physical HID usages from `internal/keymap`). The client's helper-mode injector recognises the chord and requests SAS (P2-W2-029); nothing new travels on the wire.
Hotkey path: `Matcher.Feed` returns `ActionSendCAD` with swallow = true while a client is active; `server_hotkeys.go` dispatches it to `SendCtrlAltDel(active)`; at home (no client active) it is neither matched nor swallowed (`SwallowCombos()` excludes it). `SetHotkeys` rebinding applies live. Tests use the fake client session recording injected key events.

When `s.capturer.(platform.HomeShortcutProvider)` holds, it calls `SetHomeShortcuts` with at most two shortcuts: `{ID: "lock", Description: "EdgeSync: lock to screen", Binding: Bindings.Lock.String()}` and `{ID: "panic", Description: "EdgeSync: return to this computer", Binding: Bindings.Home.String()}`; an unbound binding is skipped; jump, cycle and send-CAD are never registered (jump and cycle from home are unavailable on Wayland servers, D-114; send-CAD needs an active client). Tests use `fake.HomeShortcuts` wrapped around the fake capturer.
