# Stream brief - P5 R3 Performance benches, soak tests and tuning

Phase 5. Items: `briefs/plan-phase-5.md` section "R3". Owner tag: `[owner:R3]`. Agent: `go-dev` (`model` per the item's
tier); the review item is dispatched as `code-reviewer`. R3 may start as fill once phase P3 has exited (plan.md P5 entry).

## Scope
Build the bench harnesses defined in `perf-budgets.md` (`bench/latency`, `bench/transfer`, `bench/resources`, plus the
`bench/soak` harness for the two soak budgets added in P5-R3-001), the `edgesync-bench` CLI, a dispatchable CI bench workflow,
run every budget PB-01..PB-27 (host/loopback by agents, LAN and GUI budgets by the user), analyse misses, drive tuning items, and
re-measure until every budget passes or has a user-approved exception.

## Owned paths
- `bench/**` (except `bench/hooks/**`, which P2 W1 owns and R3 only runs), `cmd/edgesync-bench/**`,
  `.github/workflows/bench.yml` (new in P5; appended to `ownership.md` by the parent in P5-R2-001)
- `qa/manual/p5-r3-*.md`; the results log of `perf-budgets.md` is written by the parent only.
- Tuning items appended by the parent (`P5-R3-101+`) list their own files; they may touch any package with an explicit `Files:` line.

## Files to leave alone
Everything not in your item's `Files:` line; all plan files (including `perf-budgets.md`); production packages (benches import
them, never modify them; a needed API change is BLOCKED and becomes a parent decision).

## Conventions (binding)
- Decisions: D-29 (latency budget), D-35 (transport), D-44 (transfer chunks/hashes), D-49 (motion model), D-57 (defaults:
  coalescing 1 ms, heartbeat 1 s, chunk 1 MiB), D-59 (star topology), D-75/D-76 (allocation-free hot path), D-22 (agents never run
  EdgeSync binaries; loopback benches in-process are allowed).
- Budgets and bench definitions: `perf-budgets.md` (IDs PB-01..PB-24, plus PB-26/PB-27 after P5-R3-001). Mid-build results from
  P1/P3 are in its results log; reuse their harness code where it is exported (for example peer-construction helpers in
  `test/e2e`) and never fork production logic into `bench/`.
- Risks: R-01 (hook timing), R-34 (quic-go datagram path), R-42 (relay throughput), R-47 (64-machine layouts).
- Bench code is production quality: package docs, D-75 conventions, `log/slog`, goroutines owned and stoppable, tests with
  85% coverage per package. Long or LAN modes are behind CLI flags; `go test` runs only short loopback cases (each test <= 30 s).
- Loopback = two in-process peers over 127.0.0.1 with real TLS/QUIC. Real input injection (`-realinject`) exists only for the
  user's manual runs and is never used by tests.
- Default bench port 24861 (the bench never binds the agent's 24860, so a running agent on the user's PC does not conflict).
- No em dashes or en dashes anywhere; use "-". Commit `<type>(<scope>): <description> [FEAT-NNN]`, body `Item: <id>`, no
  attribution trailers, never push.

## Item P5-R3-002

- `histogram.go`: `type Histogram struct` with fixed arrays: 1 us buckets from 0 to 10 ms (10 000 buckets) then 64 log2 buckets
  up to 60 s; `Record(d time.Duration)` allocation-free (AllocsPerRun == 0); `Count()`, `Percentile(p float64) time.Duration`

  `Budgets()` for PB-01..PB-27 transcribed from `perf-budgets.md` (units: ms, us, ns, allocs, MiB, MiB/s, files/s, percent, s), and
  `Evaluate(id string, stats map[string]float64) (pass bool, detail string, err error)` (unknown ID or missing stat -> error).
- `report.go`: `type Row struct{ Date, Commit, BudgetID, Env, Result string; Pass bool }` with `Markdown()` producing exactly
  `| <date> | <commit> | <id> | <env> | <result> | yes|no |` matching the results-log columns; `WriteRows(w, rows)`.
- `TestBudgets_AllIDsPresent` checks PB-01..PB-27 each appear once.

## Item P5-R3-003
`bench/trace` (package doc: synthetic input traces for benches):
- Event: `type Event struct{ Offset time.Duration; Kind Kind; DX, DY int16; Button uint8; Down bool; Usage uint32 }`;
  kinds Motion, Button, Key, Wheel (wheel events carry the delta in 1/120 notch units in `DY`). Binary format, little-endian: header
  magic `ESTR` (4 bytes), version u16 = 1, seed u64, count u32; then 16 bytes per event: offset in microseconds u32, kind u8,
  button u8, down u8 (0/1), reserved u8 (0), dx i16, dy i16, usage u32. Document the layout in the package doc.
- `Generate(seed uint64, d time.Duration) []Event` with `math/rand/v2` PCG: one motion event per millisecond with a speed profile
  cycling slow (0.5 px/ms), medium (3 px/ms) and fast bursts (15 px/ms); a click (down+up 60 ms apart) every 2 s; a burst of 10
  key presses (down/up, 50 ms apart, HID usages for letters) every 5 s; a wheel notch (120) every 3 s.
- `Encode(w, seed, events)`, `Decode(r) (seed uint64, events []Event, err error)` validating magic, version and count against
  the remaining length.

## Item P5-R3-004
`bench/latency` - read first: `internal/engine`, `internal/session`, `internal/transport`, `internal/pairing`, `internal/pki`,
`internal/platform/fake`, and `test/e2e` helpers (reuse exported helpers; do not modify them).
- `peer.go`: build a server peer and a client peer from production packages: ephemeral identities (`internal/pki`, in memory);
  loopback: pins exchanged in-process; LAN: real pairing with the code from `-code` via `internal/pairing` (pins kept in memory,
  never written to the user's peer store); session over QUIC on the bench port; layout with the client to the right of the server.
  Server side: real server engine fed by `fake.Capturer.Emit`; client side: real client engine with a timestamping injector that
  records the monotonic time of every `MoveAbs`, `Key`, `Button`, `Wheel` call (preallocated slices, no per-call allocation).
- `latency.go`: run a trace through the server (switch to the client at start, then replay events at their offsets), measure
  (1) one-way latency per event = client inject time - (server emit time + clock offset), (2) server local segment = emit ->
  frame handed to the transport, (3) client local segment = frame received -> injector call, each into a `report.Histogram`.
  For LAN mode the client returns its timestamps over the session's control channel at the end, or writes them to `-out` for the
  server to merge (pick the option the session API allows without production changes; BLOCKED otherwise).
- `clock.go`: offset estimation from heartbeat-style exchanges: for each sample (t0 send, t1 peer receive, t2 peer send, t3 receive)
  offset = ((t1 - t0) + (t2 - t3)) / 2, choose the samples with the lowest 10% RTT, return the median offset and its spread.
- Tests (loopback, short): offset estimator against synthetic skew and jitter; a 2 s loopback run reports non-zero percentiles for
  all three segments; loopback one-way p99 <= 2 ms (PB-03 bound; if it fails on the host, report the numbers in BLOCKED instead of
  relaxing the assertion); pairing with a code succeeds in-process.

## Item P5-R3-005
- `bulk.go`: during a latency run, start a concurrent transfer through the production transfer engine of N bytes (`-bulk-size`,
  default 4 GiB for LAN, 256 MiB in tests) from a synthetic source: a deterministic pseudo-random `io.Reader`; if the transfer engine
  only accepts real files, create a sparse temp file of that size (`os.Truncate`) in `-dir` and delete it after the run.
- `switch.go`: every `-switch-interval` (default 500 ms) emit an edge contact on the server's fake capturer, measure contact emit ->
  client `ShowCursorAt` (PB-08), then return home by contact on the client side of the layout; report a histogram.
- Tests: synthetic source produces exactly N deterministic bytes without disk; loopback latency p99 under bulk <= 2 ms (PB-03 under
  bulk); switch timing measured for >= 10 switches; interval honoured within 10% (synctest where the engine permits; otherwise
  real time with a short run).

## Item P5-R3-006
`bench/transfer`:
- Baseline (`baseline.go`): raw TLS 1.3 over TCP between the same two peers using the SAME certificates, cipher configuration and
  pinning callback as the session (read them from `internal/session`/`internal/transport`; no weaker settings), streaming N bytes
  from the synthetic source; reports MiB/s.
- EdgeSync mode (`transfer.go`): the production transfer engine over a real session sending the same N bytes as one file; reports
  MiB/s and the ratio to the baseline (PB-11: >= 0.90 and >= 105 MiB/s on GbE).
- Small files (`small.go`): 10 000 files of 4 KiB in a temp tree (`-small-count`, `-small-size`), reports files/s (PB-12).
- Tests use loopback with small sizes (64 MiB, 500 files) and assert byte-exact delivery (hash compare) and well-formed reports;
  no throughput assertions on the host.

## Item P5-R3-007
`bench/resources`:
- `type Snapshot struct{ At time.Time; CPU time.Duration; RSS uint64; Handles int }`; `Sample(pid int) (Snapshot, error)`;
  `FindByName(name string) (pid int, err error)`; `Run(ctx, pid, interval) ([]Snapshot, error)`; `Summarise(s []Snapshot) Summary`
  (average CPU percent of one core, max RSS, handle-count slope via the soak slope helper or a local least-squares function).
- Windows (`sample_windows.go`): `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`, `GetProcessTimes`, `K32GetProcessMemoryInfo`
  (WorkingSetSize) and `GetProcessHandleCount` via `golang.org/x/sys/windows` or LazyDLL declarations (verify signatures on
  Microsoft Learn); `CreateToolhelp32Snapshot` for `FindByName`.
- Linux (`sample_linux.go`): CPU from the first field of `/proc/<pid>/schedstat` (nanoseconds, no CLK_TCK needed), RSS from
  `VmRSS` in `/proc/<pid>/status`, handles = entries in `/proc/<pid>/fd`, `FindByName` scans `/proc/*/comm`.
- Other OSes (`sample_other.go`): every function returns a wrapped `errors.ErrUnsupported`.
- Tests sample the test process itself (host-safe).

## Item P5-R3-008
`bench/soak`:
- `slope.go`: least-squares slope (units per hour) over samples after a warm-up cut; returns slope, intercept and R^2.
- `soak.go`: loopback mode (two in-process peers as in `bench/latency`, exercising per P5-R3-001 for `-duration`, sampling
  `runtime.NumGoroutine`, `runtime/metrics` `/memory/classes/heap/objects:bytes` and own handles via `bench/resources` every 10 s);
  LAN mode (sample the local `edgesync-agent` process found by name every 10 s while `exercise.go` drives it).
- `exercise.go`: LAN plan using the production IPC client from `internal/ipc` with the endpoint and token discovery the GUI uses:
  `JumpTo(<peer>)`/`ReturnHome` every 10 s, `SendFiles(<peer>, <generated 100 MiB file in -dir>)` every 10 min; the IPC client is
  behind an interface so tests use a fake.
- Output: CSV of samples plus a summary evaluated with `report.Evaluate("PB-26", ...)` and `("PB-27", ...)`.
- Tests: slope math, warm-up cut, a 60 s loopback soak shows no goroutine growth, the LAN plan issues the expected requests on a fake.
