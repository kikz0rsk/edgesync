## Reference: Wayland wire format (verify against the Wayland book / wayland.xml)

- **Byte order:** host order (little-endian on supported targets).
- **Header (8 bytes):** `object id u32`, then `u32 = (message size in bytes incl. header) << 16 | opcode`.
- **Maximum message size:** 4096 bytes (libwayland `WL_MAX_MESSAGE_SIZE`). Larger messages are rejected.
- **Argument types:**
  - `int`/`uint`: 32-bit.
  - `fixed`: 24.8 signed.
  - `string`: u32 length including the NUL terminator, bytes, padding to 4 (length 0 = null string).
  - `array`: u32 byte length + data padded to 4.
  - `object`: u32 id (0 = null when allow-null).
  - `new_id`: u32. For typeless `new_id` (`wl_registry.bind`) it is string interface + u32 version + u32 id.
  - `fd`: no bytes in the message; passed in ancillary `SCM_RIGHTS` data in order.
- **Object ids:**
  - `wl_display` is id 1.
  - Client-allocated ids run upward from 2.
  - Server-allocated ids start at 0xFF000000.
  - Ids are reused only after `wl_display.delete_id`.
- **Core opcodes:**
  - `wl_display` requests: `sync(callback)` 0, `get_registry(registry)` 1. Events: `error(object_id, code, message)` 0, `delete_id(id)` 1.
  - `wl_registry` request: `bind(name, interface, version, id)` 0. Events: `global(name, interface, version)` 0, `global_remove(name)` 1.

  The generator derives every other opcode from the XML (order of declaration).

Data device semantics (incoming = we are the source, outgoing and GUI = we are the target):
- **Source side:**
  1. `wl_data_device_manager.create_data_source` -> `wl_data_source.offer("text/uri-list")` -> `set_actions(copy)` (v3+).
  2. `wl_data_device.start_drag(source, origin_surface, icon=null, serial)`. The serial must come from a `wl_pointer.button` press event on `origin_surface` (implicit grab).
  3. Source events: `target(mime|null)`, `action(dnd_action)`, `send(mime, fd)` (write the data and close fd), `dnd_drop_performed`, `dnd_finished`, `cancelled`.
- **Target side:**
  1. `wl_data_device` events: `data_offer(id)`, followed by `wl_data_offer.offer(mime)` events and `source_actions`; then `enter(serial, surface, x, y, offer)`, `motion(time, x, y)`, `drop`, `leave`.
  2. Target requests: `wl_data_offer.accept(serial, mime|null)`, `set_actions(copy, copy)`, `receive(mime, fd)` (read from the pipe), and `finish()` only after a successful drop.

## Item P4-F5-005
- `dnd/wl/wire.go` (pure): message encode/decode per the reference, padding, fixed-point conversion, size checks (header size field >= 8, <= 4096, multiple of 4).
- `dnd/wl/conn.go` (pure parts) and `conn_linux.go` (socket):
  - connect to `$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY` (absolute `WAYLAND_DISPLAY` allowed);
  - `sendmsg` with `SCM_RIGHTS` for fds; a receive loop with `recvmsg` and an fd queue;
  - an object table with id allocation and reuse after `delete_id`;
  - typed event dispatch to registered handlers;
  - `Roundtrip(ctx)` via `wl_display.sync`;
  - `wl_display.error` closes the connection with a typed error carrying object, code and message.

  One goroutine owns the socket reader. Requests are serialised by a mutex. Handlers run on the reader goroutine and must not block.
- The scripted-server tests run over `net.Pipe` without fds; fd passing is covered by the weston job.

## Item P4-F5-008
Variant A incoming.
- `dnd/source.go` (pure) source-side state machine. `dnd/incoming_linux.go` runs the sequence:
  1. Map a fullscreen surface on the output under the pointer (`set_fullscreen(null)` lets the compositor choose the pointer's output; verify GNOME's behaviour from sp3.md) with a full input region.
  2. Wait for `wl_pointer.enter` on it. Inject left-down through Y1's EI injector at the current pointer position.
  3. Take the serial from the resulting `wl_pointer.button` press on our surface. Create the data source offering `text/uri-list` with copy, then `start_drag(source, surface, null, serial)`.
  4. Immediately set an empty input region and commit, so drop targets below receive the drag.
  5. On `send("text/uri-list", fd)`: stage via `transfer.Stager` (single flight), write the encoded URIs, close.
  6. `Release()` injects left-up through EI. `Cancel()` injects Escape through EI.
  7. `dnd_drop_performed` + `dnd_finished` give Dropped=true; `cancelled` gives false.
  8. Destroy the surface and source in every terminal state. Ensure the left button is released.
