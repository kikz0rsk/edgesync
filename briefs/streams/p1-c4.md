# Stream brief - P1 C4 Clipboard core and transfer core

Phase 1 core stream. Items: `briefs/plan-phase-1.md` section "C4". Owner tag: `[owner:C4]`. Starts after the
CONTRACT FREEZE (P1-F-022).

## Scope
Platform-independent clipboard and file-transfer logic: the format model and policy, pure-Go conversions used by the
OS backends (text, CF_HTML, RTF, DIB/DIBV5, TIFF), the lazy clipboard protocol (announce, offer, fetch, serve,
relay), and the transfer stack (path sanitiser, `os.Root` writer, clash naming, manifest, chunked sender and
verifying receiver, resume, manager + queue, relay). Native clipboard backends are P2; file copy-paste and DnD are
P4 (P4-F builds on the range-serving sender and the manager from here).

## Owned paths
`internal/clipboard/**`, `internal/transfer/**`; `go.mod`/`go.sum` with a claim in P1-C4-006 only.
Leave alone: session/transport (C1), agent wiring (C5), frozen contracts.

## Conventions (binding)
- Decisions: D-09, D-10, D-12, D-17, D-44, D-45, D-57, D-59, D-61, D-62, D-75. Checklist: `qa/security-review.md`
  sections 5, 6, 7.
- Consumer-defined network interfaces (no import of `internal/session`):
  ```go
  type Network interface {
      SendControl(peer peerid.ID, m msg.Control) error
      OpenData(ctx context.Context, peer peerid.ID, class transport.DataClass, h msg.DataHeader) (io.WriteCloser, error)
      Peers() []peerid.ID // connected peers: server -> all clients; client -> [server]
  }
  ```
  Each package declares its own copy (`clipboard.Network`, `transfer.Network`); the agent adapts `session.Manager`.
- Wire content is canonical (D-09): text UTF-8 with LF, HTML fragment/document UTF-8, RTF bytes, PNG. Backends convert
  to and from native forms with `internal/clipboard/convert`.
- Clipboard contents are never logged at any level; file names and paths only with `logging.Path` at Debug.
- Every decoder rejects oversized inputs before allocating (dimension and size checks first).
- No em dashes or en dashes. Commit scopes: `clipboard`, `transfer`.

## Item P1-C4-003
`cfhtml.go` (Windows "HTML Format"):
```go
func BuildCFHTML(html []byte, sourceURL string) []byte
func ParseCFHTML(b []byte) ([]byte, error)   // returns the fragment
var ErrInvalidCFHTML = ...
```
Build: header lines `Version:0.9`, `StartHTML:%010d`, `EndHTML:%010d`, `StartFragment:%010d`, `EndFragment:%010d`,
and `SourceURL:<url>` only when non-empty, each ending CRLF; body `<html><body>\r\n<!--StartFragment-->` + html +
`<!--EndFragment-->\r\n</body></html>`. Offsets are byte offsets from the start of the whole buffer (header
included); compute the header length first with placeholder widths (fixed 10 digits make this exact). Parse: read
header key/value lines until the first `<`; required keys StartHTML/EndHTML (StartFragment/EndFragment optional;
missing -> use the HTML range); every offset within `len(b)`, StartHTML <= StartFragment <= EndFragment <= EndHTML;
`-1` StartHTML/EndHTML (allowed by the spec when no context) -> use the fragment range. Port the spike's tests
(`spikes/winclip/cfhtml_test.go`).

## Item P1-C4-007
`manager.go`, `announce.go`, `offer.go`.
```go
type Config struct {
    Self peerid.ID; Role msg.Role; Backend platform.ClipboardBackend; Network Network; Policy Policy; Logger *slog.Logger
}
func NewManager(cfg Config) *Manager
func (m *Manager) Run(ctx context.Context) error                       // Backend.Watch loop
func (m *Manager) HandleControl(ctx context.Context, from peerid.ID, c msg.Control) error // ClipAnnounce, ClipFetch, ClipError
func (m *Manager) HandleData(ctx context.Context, from peerid.ID, h msg.DataHeader, r io.ReadCloser) error // clip streams
func (m *Manager) SetPolicy(p Policy)
func (m *Manager) SetRole(r msg.Role)
func (m *Manager) PeerDown(p peerid.ID)
```
- Local change: no sensitivity check (D-121: concealed content is shared like any other; logs carry formats and sizes, never content);
  `Policy.Filter`; nothing left -> nothing sent; else seq = manager counter + 1; remember `localOffer{seq, formats}`;
  send `ClipAnnounce{Origin: Self, Seq, Formats}` to every `Network.Peers()`.
- Remote announce: origin == Self -> ignore (echo); same origin with seq <= last seen from that origin -> ignore;
  otherwise it becomes the current remote clipboard (supersedes any earlier one from any origin): `Backend.Offer(
  filtered formats, provider{origin, seq})`. `Files == true` announcements: only the non-file formats are offered in
  P1 (P4-F adds files).
- The server role additionally relays (P1-C4-009).
- All state behind one mutex; `Backend.Offer` is called outside the lock.

## Item P1-C4-008
`fetch.go` (requester side, the provider) and `serve.go` (origin side).
- Provider `Render(ctx, f, w)`: request id from an atomic counter; pending map id -> waiter; send `ClipFetch{
  RequestID, Origin, Seq, MIME: f, Requester: Self}` to the origin when it is a connected peer, else to the server
  (client role); wait for `HandleData` (header `Clip.RequestID`) or `ClipError`. Timeout (D-57): 10 s when the
  announced size <= 1 MiB or unknown, else 10 s + 1 s per started MiB. Copy exactly `ClipData.Size` bytes into
  `LimitWriter(w, MaxPayload)`; fewer bytes (EOF early) or more -> error; never return nil after writing partial
  data. A newer announcement than the one the provider belongs to -> the provider fails with `ErrSuperseded`.
  `PeerDown` of the route fails pending fetches.
- Serve (`ClipFetch` with Origin == Self): seq must equal the current local announcement and the format must be in it
  (else `ClipError{conflict, "superseded"}` / `{notFound}`); `Backend.Read` into a buffer bounded by `MaxPayload`
  (`ErrTooLarge` -> `ClipError{tooLarge}`); text is checked with `convert.ValidateText` (invalid ->
  `ClipError{internal}` and a Warn log without content); then `Network.OpenData(ctx, from, DataClipboard,
  DataHeader{Clip: {RequestID, MIME, Size: len}})`, write, close. The header size is exact, so receivers can detect
  truncation.

## Item P1-C4-009
`relay.go` (server role):
- Announce from client A: handled as a remote announce (offered on the server) and forwarded unchanged to every peer
  except A.
- `ClipFetch` from B whose origin is neither Self nor B: allocate a relay id, map relay id -> (B, B's request id),
  forward `ClipFetch` with `RequestID = relay id` to the origin (not connected -> `ClipError{unavailable}` to B).
  Data from the origin with a relay id -> `OpenData` to B with B's request id and `io.Copy` (32 KiB buffer, no full
  buffering, no disk). `ClipError` from the origin -> forwarded to B with B's id. Relay entries time out like fetches.

## Item P1-C4-015
`chunk.go`: stream body for a file range = consecutive chunks; each chunk is up to 1 MiB of data immediately
followed by its 32-byte SHA-256. Chunks are aligned to 1 MiB boundaries of the file (the first chunk of a range that
starts mid-chunk is not allowed: offsets are multiples of 1 MiB).
```go
const ChunkSize = 1 << 20
func NewChunkWriter(w io.Writer) *ChunkWriter   // Write buffers up to ChunkSize then emits data+hash; Close emits the final partial chunk
func NewChunkReader(r io.Reader, length int64) *ChunkReader // Read returns verified data only; ErrChunkHash on mismatch; ErrShortStream when the stream ends before length
```
`sender.go`:
```go
type Sender struct{ ... }
func NewSender(m *Manifest) *Sender
func (s *Sender) Serve(ctx context.Context, req msg.ChunkRequest, w io.Writer) error // header already written by the caller
func (s *Sender) FileHash(index int) ([32]byte, bool)                                 // whole-file SHA-256, available after the file was fully read once
```
Serve: open `Local[index]`, `Stat` (size must equal the manifest entry, else `ErrSourceChanged`), offset must be a
multiple of ChunkSize and within the file, length = min(req.Length, size - offset) (`req.Length <= 0` means to EOF);
when offset > 0 and the file hash is not yet known, hash [0, offset) first by reading the prefix; then stream through
`ChunkWriter` while hashing; `Stat` again at the end (size or mod time changed -> `ErrSourceChanged`).

## Item P1-C4-017
`resume.go`: `func ResumeOffset(partialSize int64) int64` (floor to ChunkSize); `func (r *Receiver) Resume(index int)

## Item P1-C4-018
`manager.go` (protocol) and `queue.go` (scheduling + progress).
```go
type Direction uint8 // DirSend = 1, DirReceive
type State uint8     // StateQueued = 1, StateActive, StateCompleted, StateFailed, StateCancelled
type Info struct {
    ID string; Peer peerid.ID; Direction Direction; State State
    Files, FilesDone int; BytesTotal, BytesDone, BytesPerSecond int64; ETA time.Duration; Err error; Destination string
}
type Config struct { Self peerid.ID; Network Network; ReceiveDir func() string; Events func(Info); Logger *slog.Logger }
func NewManager(cfg Config) *Manager
func (m *Manager) Send(ctx context.Context, peer peerid.ID, paths []string, purpose msg.OfferPurpose) (string, error)
func (m *Manager) HandleControl(ctx context.Context, from peerid.ID, c msg.Control) error // FileOffer(+More), FileAccept, FileReject, ChunkRequest, Progress, Cancel, Complete, ResumeInfo
func (m *Manager) HandleData(ctx context.Context, from peerid.ID, h msg.DataHeader, r io.ReadCloser) error
func (m *Manager) Cancel(id string) error
func (m *Manager) Retry(id string) error
func (m *Manager) List() []Info
func (m *Manager) PeerDown(p peerid.ID)
func (m *Manager) Close() error
```
Protocol (receiver-driven): sender builds the manifest, sends `FileOffer` (first page, `last` set when single page)
then `FileOfferMore` pages; the receiver assembles pages (total entries and total path bytes capped at 1 000 000 and
256 MiB -> `FileReject{tooLarge}`), creates a `Receiver` in `ReceiveDir()` for purpose `send`, replies `FileAccept`,
then issues `ChunkRequest`s (whole files, offset from `Resume`), at most 4 concurrent per peer (queue semaphore);
the sender serves each on a `DataFile` stream with header `Chunk`. After the receiver has all files it sends
`Progress` with everything done; the sender replies `Complete{FileHashes}`; the receiver verifies and commits, then
the state is completed on both sides. `Cancel` from either side stops streams and marks cancelled (partials kept for
retry). Retry re-runs the receiver side with `Resume` offsets (sender side: re-offers with the same transfer id).
Queue: speed EWMA (alpha 0.3) updated every second, ETA = remaining / speed (0 when unknown); `Events` on every state
change and at most every 250 ms for progress. Purposes `clipboard` and `dnd` are refused with
`FileReject{unsupported}` until P4-F wires them.

## Item P1-C4-019
