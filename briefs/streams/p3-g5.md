# Stream brief - P3 G5 Agent end-to-end integration

Phase 3, parallel stream. Items: `briefs/plan-phase-3.md` section "G5". Owner tag: `[owner:G5]`.
G5 has no GUI dependency: it needs P3-F-006 (IPC additions) and P2-W1/W2 complete, and may run as fill while P3-F runs.

## Scope
Make `edgesync-agent` run on the real platform backends end to end (FEAT-161, FEAT-142): backend selection and
supervision, tray actions with GUI launch/focus (FEAT-144), overlay/theme/autostart/permission wiring, Wake-on-LAN
triggers (FEAT-131), lock/screensaver sync on real session events (FEAT-138), the real environment checks (Windows
firewall, tray availability; FEAT-150, FEAT-068); prove the system with in-process multi-agent end-to-end tests over
loopback on fake backends (FEAT-162, FEAT-002, FEAT-007, FEAT-031), loopback budgets (FEAT-170, FEAT-172), real-backend
integration tests on CI and the user's machines (FEAT-168), and the full manual session.

## Files you may touch
`internal/agent/**`, `test/e2e/**`, `internal/firewall/**` (new package per the P3-F-002 decision),
`cmd/edgesync-agent/main.go` (P3-G5-002 only), `internal/i18n/locales/en.toml` (claim, P3-G5-004),
`.github/workflows/ci.yml` (claim, P3-G5-018). Never edit `cmd/edgesync-agent/helper_windows.go` (W2), platform
backends, `internal/platform/*.go` (frozen), engine/session/clipboard/transfer packages: if one of them is wrong, report
BLOCKED with the defect so the parent appends a fix item for its owner.

## Dependencies (read before starting)
`internal/agent` as built by P1-C5 (composition root, options, lifecycle), `internal/platform` interfaces and
`internal/platform/fake`, `internal/platform/host`, `internal/ipc` (server and client), `internal/engine`,
`internal/session`, `internal/locksync`, `internal/wol`, `internal/discovery`, `internal/peers`, `internal/pairing`.

## Decisions
D-21 (autostart, reconnect), D-22 (integration tag, never run binaries on the host), D-34, D-46, D-49 (motion and key
model), D-57 (overlay 800 ms + 200 ms, WoL throttle 60 s, timeouts), D-59 (star, Busy), D-60 (layout authority), D-63
(injection mode), D-70 (WoL), D-71 (lock sync), D-77 (GUI launch/focus), plus the P3-F decisions (environment checks,
`internal/firewall`, single-instance GUI hand-off).

## Test rules for this stream
- E2E tests run agents in-process on `fake.Backend`, bind only `127.0.0.1` (never all interfaces: a non-loopback
  listener triggers Windows Firewall prompts on the developer PC), disable mDNS (multicast is not host-safe), use
  test-only IPC endpoint names, and use real time with generous timeouts (no `synctest` across real sockets).
- E2E tests must pass under `-race`; budget tests carry `//go:build !race` (the race detector distorts timings).
- Real-backend tests carry `//go:build integration` and are never run by agents.

## Item P3-G5-002
`cmd/edgesync-agent/main.go` + `internal/agent/backend.go`: open the backend with `host.Open(ctx, platform.Options{
Logger, SecureHelper: false (D-84: `--secure-helper` never reaches agent.Main), Injection: <config windows.injection> })`. When opening fails, the agent
keeps running its IPC server and tray (if a tray exists) and reports the failure: `GetStatus` shows the backend error,
`StatusChanged` is emitted, the tray state is TrayError; capture/injection stay off. The agent retries opening the backend every 30 s
(synctest-tested) until it succeeds, then clears the error and starts normally. Backend `Close` on shutdown. Keep what P1-C5 already did; add only what is
missing, with the named tests.

## Item P3-G5-003
`internal/agent/supervise.go` (sonnet item): one supervisor goroutine per backend capability.
- Capturer: on `KindCaptureLost` or a `Start` error, return control home (engine), then restart with backoff 250 ms ..
  30 s (D-57 values reused); on `platform.ErrPermission`, stop retrying, set the permission state (visible through
  `GetPermissions`/`PermissionStateChanged`) and resume when the permission becomes granted.
- Injector: an injection error while this machine is the active client ends the remote session (`Leave` to the
  server, which returns home) and is logged with the error kind.
- Displays: `Watch` changes produce `DesktopChanged` to the server (client role) or a layout refresh (server role).
- `CaptureStats` exposed in status (events, drops, re-installs, max callback duration).
- All goroutines owned by the supervisor and stopped by `Close`.

  `netfw.h` / Microsoft Learn before use and cite them in comments), `get_CurrentProfileTypes`,
  `get_FirewallEnabled`, `get_DefaultInboundAction`, `get_Rules` -> `get__NewEnum` -> `IEnumVARIANT` -> each rule's
