# Stream brief - P5 R5 QA matrix, documentation, spikes removal, release readiness

Phase 5. Items: `briefs/plan-phase-5.md` sections "R5" and "P5-X". Owner tag: `[owner:R5]`. Agent: `go-dev` (`model` per the
item's tier) for docs and tools; the review item is dispatched as `code-reviewer`; P5-X items are parent and user items.

## Scope
The user-facing documentation (FEAT-176), the documentation checker, the release notes and the release checklist, the removal of
the P0 spikes module after its findings are archived (FEAT-178, D-74), the QA matrix on release-candidate packages across the
user's machines plus CI evidence for macOS and X11 (FEAT-175, FEAT-168), and the phase exit: release readiness, tagging and
publishing v1.0.0 by the user, post-release verification.

## Owned paths
- `docs/**`, `README.md`, `tools/docscheck/**`, `qa/release-checklist.md`, `qa/manual/p5-r5-*.md`, `internal/config/docs_test.go`
  (new files appended to `ownership.md` by the parent in P5-R2-001)
- Deletion of `spikes/**`; claims: `Taskfile.yml` and `.github/workflows/ci.yml` (P5-R5-002), `.github/workflows/spikes.yml` and
  `.gitignore` (P5-R5-013).
- Parent only: `qa/release-readiness.md`, `qa/manual/results/**`, all plan files.

## Files to leave alone
Everything not in your item's `Files:` line; all plan files; production code (a documentation item that finds the code disagreeing
with a decision reports BLOCKED with both sides; it never edits code or picks a side).

## Conventions (binding)
- Every fact in the docs is traceable: defaults to `internal/config/defaults.go` and D-57/D-58; paths to D-69/D-48; ports to D-43;
  behaviours to the decision that defines them (including decisions appended after the P0 spikes and in P4 for per-OS file paste and
  drag-and-drop limits); packaging facts to the R1/R2 decisions and files. Read the source before writing; never describe a feature
  from memory.
- Audience: users installing and running EdgeSync (README, install, guides, troubleshooting, security) and contributors
  (development.md). Plain English, sentence-case headings, short paragraphs, tables for reference data, no marketing claims that are
  not backed by a test or measurement (performance numbers come from the `perf-budgets.md` results log).
- No em dashes or en dashes; use "-". No `TODO`/`TBD`. No paths from the developer machine. Relative links between docs.
- Docs gates: `go run ./tools/docscheck` (after P5-R5-002) exits 0.
- KDE Plasma and Windows 10 are described per P5-R5-001's answers (untested unless a machine was provided); macOS is "tested on CI
  only" (R-07).
- Commit `<type>(<scope>): <description> [FEAT-NNN]`, body `Item: <id>`, no attribution trailers, never push.

## Report format
```
FILES: <path> - <one clause>          (one line per file, or NONE)
GATES: <gate> pass|fail               (verbatim output only for a failure)
ITEMS: <item id> <FEAT-NNN, ...>
TESTS: <what the test phase must cover for this item, one line>
BLOCKED: <what stopped you, or NONE>
```
